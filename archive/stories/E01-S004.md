# E01-S004 — 建立 session bootstrap 與 current-user loading

- 狀態:DONE
- Branch:story/E01-S004-session-bootstrap-current-user
- 日期:2026-08-13

## Scope 說明

本 story 讓 `(app)` zone 從 S001 留下的 passthrough 變成真正的
authentication gate:掛載時呼叫 `authClient.getSession()`,依結果分三種
狀態(loading / 已登入 / 無 session → 導向 `/login`),並把目前使用者透過
React Context 提供給所有 `(app)` zone 的子元件。這是 S003 returnUrl 機制
「另一半」——S003 只處理「從 `/login` 回到 returnUrl」,本 story 補上
「未登入時導向 `/login` 並附帶目前路徑」。刻意排除:sidebar/header/main
chrome(S005)、實際 dashboard 內容(S007)。

## 變更檔案

- `apps/web/src/lib/session-context.tsx` — 新增:`CurrentUserContext` +
  `useCurrentUser()`。context 預設值 `null` 只會在「元件被誤用在
  provider 外」時出現(SessionGate 保證 children 只在 session 確認存在
  後才 render),因此 hook 對 `null` 一律 throw,不靜默回傳假資料。
- `apps/web/src/lib/session-context.test.tsx` — 新增:2 個測試
  (provider 內取得 session、provider 外呼叫會 throw)。
- `apps/web/src/app/(app)/session-gate.tsx` — 新增:`SessionGate`,
  掛載時呼叫一次 `getSession()`;無 session → `router.replace()` 到
  `/login?returnUrl=<目前路徑>`;session 查詢失敗(dependency error)→
  獨立的 error 狀態,**不**當成「未登入」處理、也不導向登入(AC4:
  dependency 失敗需可分類,不可誤標);成功 → 用 `CurrentUserProvider`
  包住 children。
- `apps/web/src/app/(app)/session-gate.test.tsx` — 新增:5 個測試
  (loading、成功渲染 children+context、無 session 時導向且不 render
  children、查詢失敗顯示獨立 error 狀態且不導向、`getSession` 每次
  mount 只呼叫一次)。
- `apps/web/src/app/(app)/layout.tsx` — 改為委派給 `SessionGate`
  (取代 S001 的 passthrough)。
- `apps/web/src/app/(app)/layout.test.tsx` — 更新:驗證 layout 正確接上
  `SessionGate`(細節狀態測試在 `session-gate.test.tsx`,此檔只驗證
  wiring)。
- `apps/web/src/app/(app)/page.tsx` — 加入
  `useCurrentUser()`,顯示「Signed in as {userId}」一行,作為本 story
  「current-user 真的能傳到子元件」的最小、暫時性端到端證明(見下方
  Assumptions;S007 會整個換掉這個 placeholder)。
- `packages/auth-client/src/mock.ts` — 新增匯出
  `MOCK_VALID_USER_ID`(取代硬編字串,供測試/E2E 參照,避免字串漂移)。
- `tests/e2e/specs/session-gate.spec.ts` — 新增:2 個關鍵流程 E2E
  (未登入訪問受保護路由 → 導向 `/login` 且 `returnUrl` 正確;完整
  round-trip:受保護路由 → 導向 → 登入 → 回到原路由且已認證)。
- `tests/e2e/specs/smoke.spec.ts` — 更新既有測試:`/` 現在需要登入,
  未登入訪問會導向 `/login`(此為本 story 的預期行為變更,非缺陷)。

### FIX 紀錄(VERIFY ⇄ FIX,共 1 輪)

1. `session-gate.test.tsx` 的「calls getSession exactly once per mount」
   斷言失敗(實際呼叫 2 次)。根因:測試對 `next/navigation` 的 mock
   在 `useRouter: () => ({ replace: mockReplace })` 每次呼叫都回傳
   **新的物件**,但真實的 `next/navigation` `useRouter()` 回傳穩定
   (跨 render 同一個)參照;`SessionGate` 的 `useEffect` 依賴陣列含
   `router`(這是正確、符合 `react-hooks/exhaustive-deps` 的寫法,
   lint 已驗證),所以每次 re-render 因 mock 回傳新物件而被誤判為
   依賴改變,導致 effect 多跑一次、`getSession()` 被多呼叫一次。
   修法:讓 mock 回傳穩定物件參照(`vi.hoisted` 建立一次
   `mockRouter` 物件,重複使用),同時修正 `layout.test.tsx` 的相同
   mock 模式(未觸發斷言失敗,但同一根因,一併修正避免潛在脆弱)。
   **未改動生產程式碼**——bug 純屬測試 mock 與真實 Next.js 語意不符。

修復後從 VERIFY 第一個 gate(typecheck)重新完整跑過,全部通過。

## Assumptions / 計畫外事項

1. **`(app)/page.tsx` 加入暫時性的「Signed in as {userId}」行**:若無
   任何子元件消費 `useCurrentUser()`,本 story 的核心交付(current-user
   確實能傳遞到子元件)就只能靠合成測試元件驗證,無法端到端證明。這行
   明確標記為暫時性驗證用途,E01-S007 建立真正 dashboard 時會整個替換
   掉這個 placeholder(不只是移除這一行)。
2. **Session 查詢頻率**:目前只在 `(app)` layout instance mount 時查一次
   `getSession()`,同一 SPA session 內換路由不會重新查(因為
   `(app)/layout.tsx` 本身不會因子路由切換而重新 mount)。這對 mock
   而言是合理簡化;真正的 token 過期/revoked 即時偵測需要 E02 的
   server-side 驗證機制(可能是 polling、WebSocket、或每次 API 呼叫
   時的 401 攔截),留待整合 story 處理,已在 Security AC 表格誠實記錄。
3. **returnUrl 只帶 pathname,不含 query string**:與 S003 的簡化一致
   (見 `docs/stories/E01-S003.md` Assumptions #3)。
