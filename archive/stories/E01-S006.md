- 狀態:DONE

## Scope 說明

本 story 把 S005 留下的靜態單一「首頁」sidebar 換成依角色顯示的導覽項目。
**這是 UX 層級的顯示/隱藏,不是安全邊界**——`packages/permissions` 自己的
文件註解與 Frontend/UX Boundary 都明講:UI permission hiding 只屬 UX,
真正的授權引擎(E02)不存在前,沒有任何伺服端強制力。角色→項目對應
**不是自行發明**,直接取自 `SOURCE_BASELINE.md` §7 的角色描述
(「Maintenance Engineer 使用:Maintenance Assistant...」「Sales /
Purchasing 使用:ERP Assistant...」)。

## 變更檔案

- `apps/web/src/lib/nav-items.ts` — 新增:`NAV_ITEMS`(項目→角色白名單
  對應表)與純函式 `visibleNavItems(userRoles)`。無法辨識的角色字串一律
  fail-closed(只看得到 `"all"` 項目)。
- `apps/web/src/lib/nav-items.test.ts` — 新增:8 個測試,涵蓋每個角色的
  可見項目、多角色聯集、未知角色與空角色陣列的 fail-closed 行為。
- `apps/web/src/app/(app)/_components/sidebar.tsx` — 改為呼叫
  `useCurrentUser()` + `visibleNavItems()`,不再是單一靜態項目;因為
  需要 hook,從 Server Component 改為 Client Component。
- `apps/web/src/app/(app)/_components/sidebar.test.tsx` — 更新:依角色
  情境驗證可見/不可見項目(取代 S005 的單一「首頁」斷言)。
- `apps/web/package.json` / `next.config.ts` — 新增 `@ai-km/permissions`
  workspace 依賴 + `transpilePackages` 項目(取用 `Role` 型別)。
- `packages/auth-client/src/mock.ts` — 擴充:新增
  `demo-maintenance`/`demo-sales` 兩組 mock 帳號(對應
  `maintenance_engineer`/`sales_purchasing` 角色)。沒有這兩組帳號,
  角色差異就只能在隔離的元件測試裡證明,無法透過真實登入流程做 E2E
  驗證——這是本 story 自己需要的測試 fixture,非額外擴大範圍。
- `packages/auth-client/src/mock.test.ts` — 新增:2 個測試驗證新帳號
  正確回傳對應角色。
- `tests/e2e/specs/app-shell.spec.ts` — 新增 3 個關鍵流程 E2E:
  general_user 看不到 Maintenance/ERP;maintenance_engineer 看得到
  Maintenance 看不到 ERP;sales_purchasing 相反。

## Assumptions / 計畫外事項

1. **角色→項目對應表**(`nav-items.ts` 的 `NAV_ITEMS`)是本 story 依
   SOURCE_BASELINE §7 做的具體化決策,屬於「單一 story 範圍內、低風險、
   可回退的純實作細節」(改一個陣列即可調整),故未透過 AskUserQuestion
   詢問使用者;若產品實際需求與此不同,調整成本極低。
2. **`AuthSession.roles` 保持 `string[]`,未收緊為 `Role[]`**:避免
   `packages/auth-client` 額外耦合 `packages/permissions`,且真實後端
   (E02)回傳的角色字串型別由該 contract 決定,現在收緊型別可能之後
   要改回來。`visibleNavItems` 接受 `string[]` 並在內部與已知 `Role`
   比對,未知字串安全地被當作「不符合任何白名單」。
3. **mock 新增 2 組角色帳號**(`demo-maintenance`/`demo-sales`)是本
   story 需要的測試 fixture,理由已在變更檔案清單說明;未新增
   `department_manager`/`knowledge_manager`/`it_administrator`/
   `ai_administrator`/`auditor` 帳號,因為目前 `NAV_ITEMS` 沒有任何項目
   特別綁定這些角色(它們的職責目前對應 Admin Console,屬 E11,不在
   apps/web 的 sidebar 範圍內)。
