# E01-S016 — Desktop responsive baseline

- 狀態:DONE
- Branch:story/E01-S016-desktop-responsive-baseline
- 日期:2026-08-14

## Scope 說明

本 story 建立桌面版 responsive baseline。依 SOURCE_BASELINE 的 E01-S12
基準決策(「支援主要 Desktop Resolution」;GA 才做「Tablet/Mobile
optimization」),MVP 範圍明確排除 tablet/mobile 版面,只需確保應用在
常見桌面解析度(1280x800 / 1440x900 / 1920x1080)下:

1. `<meta viewport>` 設定正確(避免瀏覽器誤用行動裝置的縮放/DPI 推斷
   邏輯,即使目前只服務桌面)。
2. 無水平捲動(overflow-x),不論是未登入的 `/login` 頁或已登入的
   app shell(sidebar + header + 內容區)。

## 變更檔案

- `apps/web/src/app/layout.tsx` — 新增 `viewport: Viewport` export
  (`width: "device-width"`, `initialScale: 1`)。Next.js App Router 會
  自動把這個 export 轉成 `<head>` 內的 `<meta name="viewport">` 標籤,
  不需手動寫 `<meta>` 元素。
- `apps/web/src/app/layout.test.tsx` — 新增:直接測試 `viewport` export
  的值(不 render,因為 RTL 對 `<html>`/`<body>` 的根節點沒有良好支援)。
- `tests/e2e/specs/responsive-baseline.spec.ts` — 新增:3 個桌面解析度
  × 2 個頁面(`/login`、已登入首頁)= 6 個 E2E 測試,驗證
  `document.documentElement.scrollWidth <= clientWidth`(無水平捲動)
  + 關鍵 chrome 元素(登入標題、主導覽、AI KM 品牌、歡迎標題)可見。

## Assumptions / 計畫外事項

1. **只驗證三個代表性桌面解析度**:1280x800(常見筆電最小可用解析度)、
   1440x900、1920x1080(常見桌上型顯示器)。未窮舉所有可能解析度,
   因 SOURCE_BASELINE 只要求「主要 Desktop Resolution」,非窮舉式支援
   宣告。
2. **Tablet/mobile 明確排除**:依 SOURCE_BASELINE GA 範圍決策,本 story
   不產生任何 tablet/mobile breakpoint 或測試,避免對 MVP 範圍做出未經
   授權的擴張承諾。
3. **未新增任何 responsive CSS(如 media query)**:目前 app shell 既有
   版面(S007-S009 建立)在三個測試解析度下已經沒有 overflow 問題,
   E2E 驗證證實現狀已符合基準,本 story 不需要修改既有元件的 CSS。
   若之後的 story 引入更寬的內容(如大型表格)導致 overflow,由該 story
   自行處理,不屬於本 baseline story 的職責範圍。
