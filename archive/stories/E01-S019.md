## Scope 說明

`apps/web/src/middleware.ts`(E01-S001)當時的註解已經預先劃好界線:
「Client-side interaction telemetry (event hooks) 是 E01-S019 的職責」
——middleware 只處理 HTTP request/response 層的 correlation id,本 story
補上**前端互動層**的結構化事件機制。

依 Preconditions,這是給 E14(Audit, Security & Observability,Team B)
未來的遙測/稽核端點準備的前端 hook,`contracts/openapi/core.yaml`
目前沒有任何 path,所以沒有真實 endpoint 可打——套用整個 session 都在用
的既有模式(比照 `@ai-km/auth-client` 應對尚未存在的 E02):建立
typed 介面 + 目前先經由既有 `logger` 輸出,呼叫端的程式碼未來不需要
改動,只需要把 `trackEvent` 內部的實作換成真的 HTTP 呼叫。

## 設計決策

1. **`trackEvent(name, options?)` 是同步、絕不 throw 的**:遙測本質上
   不能影響呼叫端的業務邏輯——如果送出遙測事件本身會失敗或阻塞,不能
   因此讓使用者的登入或導覽跟著壞掉。
2. **`correlationId` 可由呼叫端提供或自動產生**:像登入這種已經有
   自己 correlation id 的既有操作(`login-form.tsx` 每次送出都會產生
   一個),讓 `login_attempt`/`login_success`/`login_failure` 三個
   遙測事件共用同一個 id,才能跟既有的 `logger.info/warn` 呼叫（同一個
   id)在除錯時對得起來;沒有現成 id 的情境(如單純的 page view)則
   自動產生一個新的。
3. **`usePageViewTelemetry()` 掛在兩個 zone 的入口,不是逐頁掛**:
   `(app)/session-gate.tsx`(涵蓋 (app) 底下所有現在與未來的頁面)+
   `(public)/login/login-form.tsx`(目前 (public) zone 唯一的頁面)。
   與 E01-S017 RoleGuard「掛一次、之後的頁面自動涵蓋」是同一個模式。
4. **登入的遙測 payload 刻意不含 `username`**:雖然既有的
   `logger.info("login attempt", {correlationId, username})` 已經包含
   username(維持不動,不動既有的除錯 log),但新的 `trackEvent` 呼叫
   只帶 `correlationId`(失敗時另外帶機器可讀的 `code`)。理由:遙測
   最終是要送到 E14 的稽核/分析管線,受眾與保留政策跟開發用的
   console log 不同,即使 username 本身不算 credential/secret,還是
   採取比 AC7 字面要求更保守的做法。

## Assumptions / 計畫外事項

1. **沒有窮舉式地把 `trackEvent` 加到每一個現有互動點**:只挑了
   page view(最通用)與 login 的 attempt/success/failure(AC6 最直接
   要求的「成功與失敗路徑」範例)兩類真實掛載點,證明機制真的被使用、
   不是死程式碼。其餘互動(如 logout、nav 點擊)留給各自的 domain
   story 未來按需採用,避免本 thin slice 變成一次橫掃全 repo 的大改。
2. **沒有建立獨立的 `@ai-km/telemetry-client` 共用套件**:目前只有
   `apps/web` 需要;`apps/admin`(E11 尚未開工)沒有實際需求可以驗證
   設計是否合適。比照 `packages/logger` 已經是共用套件的先例,若未來
   `apps/admin` 真的需要,屆時再抽出共用套件,不提前為假設性需求
   設計。
3. **`trackEvent` 目前的「傳輸層」就是既有的 `logger`**:還沒有獨立於
   `console` 輸出之外的傳輸機制(如真的送 HTTP request 到某個
   endpoint)——因為目前沒有這樣的 endpoint 存在。E2E 測試因此透過
   攔截 console 輸出驗證,這是本 story 現況下最貼近真實的驗證方式,
   非權宜之計。
