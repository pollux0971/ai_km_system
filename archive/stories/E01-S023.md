# E01-S023 — App shell Material 3 化

- 狀態:approved
- Branch:story/E01-S023-app-shell-m3
- 日期:2026-08-29(SELF-REVIEW 修正:2026-08-29)

## Scope 說明

Navigation rail/drawer/modal 三態、top app bar、FAB「開始新對話」、M3
list(歷史對話)、M3 menu(user-menu／notification-center)的 M3 化。只改
className/wrapper/最小新互動,不改任何既有 DOM 結構、accessible
name、role 或路由。

## 變更檔案

- `apps/web/src/app/(app)/_components/sidebar.tsx` — 每個主導覽項目、
  FAB、歷史對話項目加 `<Icon>`(全部不帶 `label`,渲染為 `aria-hidden`,
  不影響 accessible name);歷史對話重構為 M3 list item(leading icon +
  headline span 在 `<a>` 內,supporting text `lastMessagePreview` 作為
  `<a>` 的**手足元素**,不是嵌套在裡面——嵌套會把 preview 文字併入連結
  的 accessible name,破壞既有
  `getByRole("link", { name: "產品保固政策詢問" })` 斷言)。
- `apps/web/src/app/(app)/_components/app-shell.tsx` — 新增
  `data-nav-mode`(`drawer` >=1240 / `rail` 840–1239 / `modal` <840),
  純 client-side 依 `window.innerWidth` 計算、resize 時重算;初始值為
  `undefined`,只在 `useEffect` 內設定,SSR 與首次繪製都不含這個屬性,
  無 hydration mismatch。`<840` 時渲染漢堡按鈕(`aria-label="開啟導覽
  選單"`、`aria-expanded`)開啟 modal drawer + scrim;Esc 與點擊 scrim
  皆可關閉,關閉後焦點回到漢堡按鈕。`<Sidebar>` 在所有模式下都不會被
  卸載,只是外層 class 改變。
- `apps/web/src/app/(app)/_components/header.tsx` — 加
  `app-header--m3` class,DOM/文字/role 不變。
- `apps/web/src/app/(app)/_components/user-menu.tsx` /
  `notification-center.tsx` — inline `style={{...}}` 改為
  `.m3-menu-anchor`/`.m3-menu-trigger`/`.m3-menu`/`.m3-menu-item` 等
  class,套用 M3 elevation/shape/color token;trigger 加 `<Icon>`(不帶
  label,accessible name 不變);`role="menu"`/`role="dialog"`、
  `aria-expanded`、`aria-haspopup`、按鈕/連結文字全部逐字不變。
- `apps/web/src/app/globals.css` — 新增 `/* ---------- M3 shell
  (E01-S023) ---------- */` 區段:nav-mode 版面(rail 收窄+icon-only

### axe 發現的真問題(誠實記錄,非計畫外變更——直接對應 AC5)

新增的 axe 測試第一次跑就抓到 `.sidebar-history-title`(「歷史對話」
標題)的既有 `opacity: 0.75` 把一組本來合格(E01-S021 對比報告已驗證)
的 `on-surface-variant`/`surface-container-high` 配對拖到 4.1:1(低於
小字 4.5:1 門檻);同一區塊本story新增的 `.sidebar-history-preview`
也犯了同樣的錯(`opacity: 0.7`,3.65:1)。兩者移除 opacity dimming 後
重跑 axe 為 0 violation。**額外主動修正**了同一模式的
`.sidebar-history .sidebar-empty`(`opacity: 0.65`)——這個狀態當下沒有
被 axe 掃到只是因為畫面上剛好沒有渲染(有 3 個既有對話),不是它本身
沒問題;既然同一段 CSS、同一個 bug class 就在旁邊,一併修正而非留下
已知但未觸發的缺陷。三處修正後重新截圖,`docs/design/app-shell-m3.md`
的截圖對應修正後的樣式。

### SELF-REVIEW 階段發現的第二個問題(誠實記錄,非一開始就做對)

`/story-review` 自審時針對「移除 opacity 後 supporting text 是否仍在視覺上
次於主文字」這點深查,發現**確實有回歸**:`.sidebar-history-link`(標題)
與 `.sidebar-history-preview`(supporting text)修正前都是
`color: var(--sidebar-text)`(`on-surface-variant`)——同一個 token。移除
opacity dimming 解決了 axe 抓到的對比度問題,但也連帶讓標題與 preview
變成完全同色,只剩 font-size(0.9rem vs 0.78rem)區分,層次比修正前更弱,
且偏離這個 story 其他地方遵循的 M3 慣例(headline = on-surface,
supporting text = on-surface-variant)。

**修正**:`.sidebar-history-link` 改為 `color: var(--sidebar-text-strong)`
(`on-surface`),`.sidebar-history-preview` 維持 `var(--sidebar-text)`
(`on-surface-variant`)。這個方向只會**提高**對比度,不可能引入新的 axe
違規(已重新驗證,見下方 Gate 紀錄)。修正後重新產生全部 6 張截圖。
