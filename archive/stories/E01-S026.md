   共 6 張。
4. **第一輪截圖發現真 bug**：背景圓只有單層 fallback
   `var(--md-sys-color-surface-container, #e3e2e6)`，light mode 看起來

   `--surface-2` token）後重新截圖確認修正。詳細推理見
   `docs/design/brand-assets.md`「Token 對照」一節。

6. 測試頁刪除（從未 `git add`，`git status` 於刪除後確認乾淨）；

## Assumptions / 計畫外事項

1. **兩個允許清單之外、但技術上必要的新檔案**：
   - `apps/web/src/components/illustrations/empty-state-illustrations.tsx`：
     `illustration` prop 型別是 `ReactNode`，但 `next.config.ts` 沒有設定
     SVGR loader，無法直接 `import` `.svg` 檔案當 React component（已確認
     `next.config.ts` 內容,禁止清單本身也不包含它,不打算為了這個新增
     去改 build 設定）。若不建立這個檔案，「三處接入元件各一行」在技術上
     無法達成（唯一替代方案是把完整 SVG markup 直接貼進三個接入元件裡，
     那既不是「一行」也會讓三個檔案各自維護一份重複的插圖標記）。這與
     E03-S042 VoiceVisualizer 已經建立的先例完全一致（一份 `public/`
     靜態 SVG 資產 + 一份 inline JSX 對應版本，非本 story 新發明的模式）。
   - `apps/web/src/app/favicon.ico`：Next.js App Router 對 `favicon.ico`
     的慣例特殊檔案路徑，與允許清單明文列出的 `apps/web/src/app/icon.svg`
     是**同一個目錄、同一種機制**（Next 自動偵測並產生對應路由）。若只把
     `favicon.ico` 放在 `apps/web/public/brand/`（素材目錄本身允許），
     它會被服務在 `/brand/favicon.ico`，瀏覽器預設請求的
     `/favicon.ico`（網域根目錄）不會拿到它，AC4「favicon.ico 由 Next
     正確輸出」也就無法用 build 產物驗證。兩個檔案內容相同（
     `apps/web/public/brand/favicon.ico` 是設計資產源頭，
     `apps/web/src/app/favicon.ico` 是實際被服務的那份）。
   兩者皆為**純新增**檔案，不觸碰、不修改任何禁止清單內的路徑或既有
   檔案，性質與已明文允許的 `app/icon.svg` 相同，故視為同一類「必要技術
   延伸」而非違反邊界；比照本 session 之前 E12-S031/E03-S041 遇到類似
   情況時的處理原則（純加法、零 business logic、與允許清單同性質）。
2. **「三處接入」的具體元件選擇是本 story 自己的判斷**（ASSUMPTION）：
   spec 只寫「對話清單／知識文件列表／搜尋無結果」三個情境名稱，未逐字
   指定對應到哪三個檔案。詳細推理與可能的替代方案見
   `docs/design/brand-assets.md`「接入點選擇的理由」一節；若使用者/總
   指揮認為應該對應到不同檔案（例如 `knowledge-list.tsx` 而非
   `knowledge-document-list.tsx` 承接 no-documents），只需調整這三個
   `illustration=` 的值，不影響其餘實作。
3. **Logo lockup 用 `<text>` 而非轉外框**（spec 明文二擇一，已記錄於
   `brand-assets.md`）：E01-S022（自託管字型）尚未落地，且沒有實際
   Roboto 字型檔可用來手動描邊出精確外框（手動近似只會品質更差），
   `<text>` 目前 fallback 到系統字型，E01-S022 完成後自動改用自託管
   Roboto，無需改檔案。
4. **背景圓顏色的三層 fallback 是截圖階段抓到真 bug 後才加上的**（非
   原本設計)——完整說明見上方 L3 一節與 `brand-assets.md`「Token 對照」。
5. **`apple-touch-icon.png` 用實心白底而非透明**：iOS 會把 PNG 透明區域
   填成黑色（已知踩雷點），改用 `background: "#ffffff"`（`@resvg/resvg-js`
   的渲染參數）避免。
6. **favicon 系（`favicon.svg`/`icon.svg`/`favicon.ico`/
   `apple-touch-icon.png`）固定用品牌藍 `#1e56a0`，而非 `currentColor`**：
   這些是瀏覽器 chrome／iOS 主畫面渲染，沒有頁面 CSS context 可繼承
   `currentColor`（在 app 內渲染的 `logo-mark.svg`/`logo-lockup.svg` 才用
   `currentColor`）——理由已寫進 `brand-assets.md`，非隨意混用兩種上色
   策略。
