# E03-S014 — Citation preview drawer

- 狀態:DONE
- Branch:story/E03-S014-citation-preview-drawer
- 日期:2026-08-14

## Scope 說明

SOURCE_BASELINE.md 對 S14 給了標題加上一個三項條列（第 1168-1174 行）：

```
E03-S14 Citation Preview

顯示：

- File
- Page
- Snippet
```

比 S13 多一點——明確指定要顯示的三個欄位——但完全沒有資料形狀、互動
方式（點擊?hover?)或失敗行為的定義。epic 檔案展開版把標題具體化為
「Citation preview drawer」,是本 story 採用「drawer」（面板)作為具體
UI 呈現方式的依據，而非憑空選擇。

明確排除:
- S15「Citation Open Source」（開啟原始來源文件)——本 story 只做預覽,
  不做「開啟」。
- S16「Citation Permission Error」（引用來源權限錯誤)——本 story 的
  NOT_FOUND 是資料層級的「找不到」,不是權限層級的「無權限」;真正的
  權限錯誤處理留給 S16 這個獨立 story。
- S13 的 Security AC「Unauthorized source 不得進入 LLM context、
  citation、export 或 logs」延續 S13 已確立的 N/A 論證——沒有真正的
  RAG/citation 後端（E04 尚不存在),mock 的引用來源完全沒有連結任何
  真實文件或權限。

## 設計決策

1. **`getCitationSource(id)` 直接回傳最終結果**
   （`Result<CitationSource, ApiError>`,查無資料時直接
   `{ ok: false, error: { code: "NOT_FOUND" } }`),不是像
   `getConversation` 那樣回傳 `T | null` 交給上層呼叫者轉譯——因為
   `getCitationSource` 唯一的呼叫者（`citation-preview-drawer.tsx`)
   本身就是最終消費者,沒有中間層需要那個「軟性 null」的區分,直接給
   最終答案更單純。這個決策修正了一次真正的實作錯誤（見下方除錯
   過程)。
2. **兩筆 mock 資料（"1"、"2"),皆明確標示為模擬內容**——不虛構具體
   業務文件內容,延續 `message-content.tsx` 解析 `[N]` 標記、
   E03-S005 從不發明真實模型廠商名稱的同一套紀律。兩筆內容刻意不同
   （不同檔名標籤、不同頁碼),讓測試能證明「不同引用 id 顯示不同
   內容」,而不是永遠顯示同一份靜態內容。
3. **`<sup>` 內嵌 `<button>`,不是把 `<sup>` 換成 `<button>`**——`<sup>`
   保留 S13 原本的 `aria-label`（「引用來源 N」,描述這是什麼)完全
   不變,S13 既有測試因此零回歸;新增的內層 `<button>` 帶自己的
   `aria-label`（「檢視引用來源 N」,描述點擊這個動作),是真正的點擊
   目標。標準 HTML 允許 `<sup>` 內含互動元素,不影響 `<sup>` 自身的
   role 判定。
4. **`CitationPreviewDrawer` 用 `citationId: string | null` 同時代表
   「是否開啟」與「顯示哪一筆」**,整個 thread 只有一個共用的 drawer
   （不是每則訊息各自一個),點擊不同引用直接切換內容,不需要先關閉——
   這是單一共用預覽面板最自然、不令人意外的行為。
5. **非 modal**——渲染成普通 in-flow 區塊,不做 focus trap/遮罩,因為
   規格完全沒有要求 modal 行為,替一個未定義的需求先做 focus trap 是
   投機性的超額範圍。
6. **「找不到引用來源」透過既有共用元件 `ErrorMessage` 的
   `code="NOT_FOUND"` 呈現**（`@ai-km/ui` 已經有這個 code 對應的安全
   通用訊息),不是自己發明一個 `EmptyState` 文案——依 id 查找卻查無
   資料,語意上更接近既有的 NOT_FOUND 慣例（`lib/messages.ts` 的
   `sendMessage`/`receiveAssistantReply`),而非「集合本來就是空的」
   這種 EmptyState 語意。NOT_FOUND 這個 code 額外傳入更具體的
   `message="找不到這個引用來源。"`（沿用 `ErrorMessage` 自己文件註解
   描述的「同一個 code 不同情境用不同文案」模式,如同 login 頁的
   context-specific 覆寫),任何其他/未來的錯誤 code 則落回共用元件
   自己的通用對應,不替未知情況發明新文案。
7. **新增 `conversation_citation_preview_attempt/_success/_failure`
   telemetry 三件套**,延續既有命名規則（`conversation_` 前綴,
   attempt/success/failure 三態);`citationId` 放進 properties（純
   數字識別碼,不是內容本身,不違反既有的「不記錄原文」紀律)。

**兩輪除錯,皆已定位根因,誠實記錄**:

1. **`citation-preview.spec.ts` 自己的 E2E locator 誤用**:第一次跑
   `drawer.getByText("片段")` 失敗,錯誤是「strict mode violation,
   resolved to 2 elements」——因為 Playwright 的 `getByText` 預設不是
   精確比對,「片段」這個標籤文字剛好是 snippet 內容「（模擬片段）...」
   的子字串,兩個都命中。這是我自己測試寫法的問題,不是實作問題。
   修正:三個欄位標籤的查詢都加上 `{ exact: true }`。
2. **`message-content.tsx` 的 `noUncheckedIndexedAccess` typecheck
   錯誤**:一開始用 `match[1]`（`/^\[(\d+)\]$/.exec(part)` 的捕獲群組)
   當作 `citationId` 傳給要求 `string` 的 `onCitationClick`,但這個
   repo 的 `tsconfig.base.json` 開了 `noUncheckedIndexedAccess`,把
   所有正規表達式捕獲群組存取都型別為 `string | undefined`（即使
   邏輯上這裡一定有值),導致 `pnpm typecheck` 紅燈。修正:改用
   `part.slice(1, -1)`（既然已經用 `/^\[\d+\]$/.test(part)` 確認過
   `part` 就是 `[<digits>]` 這個精確形狀,直接切掉頭尾中括號即可取得
   純數字字串),不使用 `!` 非空斷言（這個 repo 完整 grep 過,找不到
   任何地方用過 `!` 斷言,不引入新的、與既有風格不一致的慣例)。
   同時發現並修正一個真正的設計不一致:`lib/citations.ts` 最初的
   實作是照抄 `getConversation` 的 `T | null` 慣例
   （`{ ok: true, value: null }` 代表查無資料),但
   `citation-preview-drawer.tsx` 從一開始就是照「直接回傳 NOT_FOUND」
   的假設寫的（因為只有一個呼叫者,不需要軟性 null),兩者對不上,
   被 `citations.test.ts` 的「未知 id 應該 fail-closed」測試抓到
   （`expected true to be false`,因為當時的 `ok` 一直是 `true`)。
   修正:把 `citations.ts` 改成直接回傳
   `{ ok: false, error: { code: "NOT_FOUND" } }`,與 drawer 元件的
   假設一致（見設計決策 1 的完整理由)。

## Assumptions / 計畫外事項

1. **`getCitationSource` 的錯誤模型從 `T | null` 改為直接
   `Result<T, ApiError>`**:SOURCE_BASELINE 未定義失敗行為;選擇直接
   回傳最終結果（而非 `getConversation` 式的軟性 null)是因為這個
   函式只有一個呼叫者,沒有中間層需要那個區分——詳見設計決策 1 與
   除錯過程 2。這不是計畫外變更（一開始就是 `citations.ts` 自己內部
   實作與設計意圖不一致,在同一個 story 的 IMPLEMENT 階段被自己的
   測試抓到並修正,未曾對外暴露不一致的版本)。
2. **「找不到引用來源」重用既有 `ErrorMessage` 元件而非新建
   `EmptyState` 文案**:SOURCE_BASELINE 未定義,選擇與既有 NOT_FOUND
   慣例（`lib/messages.ts`)一致的呈現方式,而非為這個情境發明新的
   UI 語彙。
3. **Drawer 為非 modal、無 focus trap**:規格未要求 modal 行為,依
   「不做未要求的額外範圍」原則不主動加上。
4. **`MOCK_CITATION_SOURCES` 只定義 "1"、"2" 兩筆**:目前
   `lib/streaming.ts` 的 `MOCK_REPLY` 只會產生 `[1]`,"2" 純粹是為了
   讓測試能證明「不同 id 顯示不同內容」而額外定義,不代表產品上真的
   會出現第二個引用來源。
