# E03-S016 — Citation permission-error UX

- 狀態:DONE
- Branch:story/E03-S016-citation-permission-error
- 日期:2026-08-14

## Scope 說明

SOURCE_BASELINE.md 對 S16 只給標題「E03-S16 Citation Permission
Error」（第 1182 行),完全沒有內文——與 S15 一樣是引用三部曲之後、
最少的一個。epic 檔展開版把標題具體化為「Citation permission-error
UX」——明確是**呈現層**的 story,不是「打造一套真正的引用來源權限
系統」。

這個 story 的 Security/Authorization Acceptance 明確提到 E02
（Identity, RBAC & Authorization,Team B)與「Unauthorized source
不得進入 LLM context、citation、export 或 logs」,但 E02 的真正
contract 不存在,也沒有任何真正的文件/來源層級權限系統（E04 也不
存在)。依「不發明 contract」鐵律,不能假裝有一個真正的 per-document
權限 API。但 epic 標題明確把這個 story 界定為「UX」——給定某個引用
來源「已經是」permission-denied 的狀態,如何正確呈現(deny-wins:
絕不洩漏內容),這件事完全不需要真正的權限系統就能誠實建構與測試,
延續 S13-S15 已確立的「用本地、明確標示的 mock 資料展示行為」紀律。
因此判斷:**不 BLOCKED**,以 mock 權限旗標的方式實作。

明確排除:
- 不是真正的 per-document ABAC/RBAC——`FORBIDDEN_CITATION_IDS` 是純
  前端 mock 常數,不是呼叫任何權限服務。
- 不改變 badge 本身的外觀（例如鎖頭圖示)——使用者要點擊之後才會
  發現這個引用來源被拒絕,這是刻意的簡化(真正系統若要「點擊前就
  預先標示」需要在渲染訊息前就知道每個引用的權限狀態,是規格完全
  沒有提到的不同能力)。

## 設計決策

1. **`FORBIDDEN` 檢查在 `getCitationSource` 內部排在 found/not-found
   查詢之前**——刻意對應 Security Acceptance 的「Authorization 在
   資料取得...之前完成」,即使只是 mock 規模:先決定「有沒有權限」,
   不是「查不到內容之後才順便算作沒權限」的副作用。
2. **重用既有的 `ErrorMessage` 共用元件與其既有的 `FORBIDDEN`
   （403)通用對應**——不新建元件、不新建 UI 狀態機。drawer
   （`citation-preview-drawer.tsx`)與獨立頁面
   （`citation-source-view.tsx`)原本就有的 `kind/status === "error"`
   分支,現在多處理一個 code,結構完全沒變。
3. **新增 `CITATION_ERROR_MESSAGES`（`lib/citations.ts` 匯出),集中
   NOT_FOUND 與 FORBIDDEN 兩個 code 的專屬文案**——避免 drawer 與
   獨立頁面各自維護一份可能走鐘的文案（S14/S15 原本各自用一份內嵌
   三元運算子只處理 NOT_FOUND,現在改成共用一份 map,兩處元件都改用
   `CITATION_ERROR_MESSAGES[state.code]`)。任何不在這個 map 裡的
   code（例如未來真正的 SERVER_ERROR)仍然落回 `ErrorMessage` 自己
   的通用對應。
4. **Deny-wins 是結構性保證,不只是文案選擇**——drawer 的
   `kind === "error"` 與 `kind === "loaded"`（唯一渲染
   File/Page/Snippet 的分支)互斥;獨立頁面的 `status === "error"`
   是一個**獨立的 `return`**,不是與內容並列的條件片段。FORBIDDEN
   結果在程式碼結構上就不可能同時渲染到內容分支。
5. **`id: "3"` 保留給 FORBIDDEN,不嵌入 `lib/streaming.ts` 的
   `MOCK_REPLY`**——與 S14 的 `id: "2"` 相同慣例(只為測試存在,不透過
   真實對話流程自然出現)。具體核對過:若加入 MOCK_REPLY,會讓一般
   demo 對話永遠多一個「一定會被拒絕」的引用,且會讓
   `citation-badge.spec.ts` 既有的單一 `getByRole("superscript")`
   locator（在同一個 list item 內)壞掉——為了一個規格本來就把這個
   story 界定為「呈現層」而非「真實觸發頻率」的東西,不值得承擔這個
   無關的回歸風險。
6. **不新增 telemetry 事件**——FORBIDDEN 只是既有
   `conversation_citation_preview_failure`/
   `conversation_citation_open_source_failure` 事件的另一個 `code`
   值,不是新的動作類型,沿用既有事件即可。

## 變更檔案

- `apps/web/src/lib/citations.ts`——新增 `FORBIDDEN_CITATION_IDS`
  （目前只有 `"3"`)、匯出 `CITATION_ERROR_MESSAGES`;
  `getCitationSource` 在 found/not-found 查詢之前先檢查 forbidden。
- `apps/web/src/lib/citations.test.ts`——新增 2 個測試:`"3"` 回傳
  FORBIDDEN、FORBIDDEN 結果的 `Result` 物件結構性地沒有 `value`
  欄位（型別層級的 deny-wins 證明,不只是「碰巧是空的」)。
- `apps/web/src/app/(app)/conversations/[id]/_components/citation-preview-drawer.tsx`
  ——改用 `CITATION_ERROR_MESSAGES[state.code]` 取代原本只處理
  NOT_FOUND 的三元運算子。
- `apps/web/src/app/(app)/conversations/[id]/_components/citation-preview-drawer.test.tsx`
  ——新增 3 個測試:FORBIDDEN 專屬文案、**security-negative:FORBIDDEN
  時 File/Page/Snippet 與「開啟原始來源」連結完全不會渲染**、
  FORBIDDEN 觸發 failure telemetry 而非 success。
- `apps/web/src/app/(app)/citations/[id]/_components/citation-source-view.tsx`
  ——同上,改用 `CITATION_ERROR_MESSAGES[state.code]`。
- `apps/web/src/app/(app)/citations/[id]/_components/citation-source-view.test.tsx`
  ——同上,新增 3 個對應測試（含 security-negative:FORBIDDEN 時

**兩輪除錯,皆已定位根因,誠實記錄**:

1. **既有的 `vi.mock("@/lib/citations", ...)` 手動 mock 工廠沒有提供
   新匯出的 `CITATION_ERROR_MESSAGES`**:`citation-preview-drawer.tsx`
   與 `citation-source-view.tsx` 都直接讀取這個模組層級常數（不是
   透過函式呼叫),但兩個測試檔既有的 `vi.mock` 工廠只回傳
   `{ getCitationSource: vi.fn() }`,導致元件渲染到 error 分支時
   拋出「No "CITATION_ERROR_MESSAGES" export is defined on the mock」
   例外。修正:兩個測試檔的 mock 工廠都補上
   `CITATION_ERROR_MESSAGES`（與真實模組相同的兩筆文案,維持這個
   檔案既有的「plain synchronous factory,不用 vi.importActual」
   慣例)。
2. **`citations.ts` 自己內部又踩到一次 `noUncheckedIndexedAccess`**
   （與 E03-S014 的 `message-content.tsx` 同一類問題,但這次是
   `Record<string, string>` 的**點記法**屬性存取,不是陣列索引)：
   `getCitationSource` 一開始想直接讀
   `CITATION_ERROR_MESSAGES.FORBIDDEN`/`.NOT_FOUND` 來組出
   `ApiError.message`,但 `Record<string, string>` 底層就是一個
   index signature,`noUncheckedIndexedAccess` 開啟時,連用點記法
   存取都會被型別為 `string | undefined`,無法指派給要求
   `string` 的 `ApiError.message`。修正:`getCitationSource` 內部
   改回直接用字面字串常值（與 S014 原本 NOT_FOUND 的寫法一致),
   `CITATION_ERROR_MESSAGES` 純粹作為**外部消費者**（兩個 UI 元件)
   的共用文案來源,不被 `citations.ts` 自己回頭引用——doc comment
   已明確記錄這是刻意的、非巧合的文字重複（改一處要記得改另一處),
   不是複製貼上遺漏。

### Security / Authorization Acceptance

**這是 S13-S15 都標記 N/A、明確指向本 story 的那條 AC**:「Unauthorized
source 不得進入 LLM context、citation、export 或 logs」。本 story
在目前 mock 範圍內具體落實:`getCitationSource` 對 forbidden id 回傳
的 `Result` 型別上就沒有 `CitationSource`（`ok: false` 的分支結構上
不帶 `value`),兩個 UI 元件的 render 邏輯結構上也不存在「同時顯示
錯誤又洩漏內容」的路徑。**仍然明確保留的限制**:這是 UX 呈現層,不是
真正的 per-document 權限系統——真正的授權判斷需要等 E02 contract
與真正的來源/權限資料存在後才能落地,現在只是確保「一旦系統知道
某個來源不該顯示,UI 絕不會意外洩漏」這個呈現面的保證。

### Data / Contract Acceptance

未修改 `contracts/`,未新增任何持久化欄位——`FORBIDDEN_CITATION_IDS`
是純記憶體 mock 常數,不寫入 sessionStorage。

## Assumptions / 計畫外事項

1. **權限判斷是純前端 mock 常數,不是真正的授權系統**:SOURCE_BASELINE
   與 epic 檔都沒有定義真正的權限資料模型;E02 contract 不存在。
   選擇建構「呈現層」（給定已知的 forbidden 狀態,正確呈現)而非
   BLOCKED,因為 epic 展開標題明確把這個 story 定義為「UX」,且
   deny-wins 的呈現保證可以在不發明真正 contract 的前提下誠實建構
   與測試。
2. **`id: "3"` 未嵌入 `MOCK_REPLY`**:見設計決策 5——具體核對過會
   造成 `citation-badge.spec.ts` 的既有 locator 回歸,為一個規格
   界定為「呈現層」的 story 承擔這個風險沒有必要。
3. **沒有新增 telemetry 事件**:FORBIDDEN 是既有 failure 事件的一個
   新 code 值,不是新的動作類型,沿用既有的
   `conversation_citation_preview_failure`/
   `conversation_citation_open_source_failure`。
4. **Badge 本身外觀不變**:使用者要點擊之後才知道某個引用被拒絕,
   不會事先標示——規格沒有定義「點擊前預先顯示權限狀態」這個能力,
   依「不發明」原則不新增。
