## 與 E03-S037 的耦合(誠實記錄,不隱藏)
`touchConversationLastMessage` 依 spec 技術決策改為 deprecated no-op:「改為 deprecated no-op 並於 E03-S037 移除(server 已連動)」。這是**必要**的改動,不是偷懶——contract 的 `UpdateConversationRequest`(`additionalProperties: false`)根本沒有 `lastMessageAt`/`lastMessagePreview` 欄位,server 端要等訊息 endpoint(E03-S037)接上才會自動連動這兩個欄位;繼續讓這個函式「假裝做了什麼」等於自己發明一個 contract 沒有的欄位,直接違反 CLAUDE.md 鐵律 1。

這個改動的直接後果:`apps/web/src/lib/messages.ts`(呼叫 `touchConversationLastMessage` 與 `getConversation`,但**本 story 的允許修改清單明文禁止碰這個檔案**——`messages.ts` 屬於 E03-S037 的允許清單)在 `pnpm --filter @ai-km/web test` 全量跑時會有 **6 個既有測試(`messages.test.ts`,共 70 個)** 轉紅:

| 測試 | 紅的原因 |
|---|---|
| `sendMessage > updates the conversation's lastMessageAt/lastMessagePreview to reflect the sent message` | `touchConversationLastMessage` 變 no-op,`getConversation` 讀回的 preview 不再更新 |
| `sendMessage > uses an attachment-count placeholder preview for an attachment-only message` | 同上 |
| `receiveAssistantReply > updates the conversation's lastMessageAt/lastMessagePreview to reflect the reply` | 同上 |
| `reviseMessage > updates the conversation's lastMessagePreview to reflect the revised content` | 同上 |
| `sendMessage > fails closed with NOT_FOUND for an id that doesn't exist` | `messages.ts` 內部呼叫 `getConversation("does-not-exist")`,非 UUID 現在被 contract 的 `format:uuid` 擋成 400 `VALIDATION_ERROR`,而非原本的 `NOT_FOUND` |
| `receiveAssistantReply > fails closed with NOT_FOUND for an id that doesn't exist` | 同上 |

這正是 spec 自己標注的「Parallel-safe: No 對 E03-S037(連續)」——這個耦合是設計上的必然,不是本 story 的缺陷。**因此:S036 的 commit 不會單獨推上 main**;會緊接著在同一個 branch 系列完成 E03-S037(把 `messages.ts` 也轉成 typed-client adapter、移除 `touchConversationLastMessage` 的呼叫與這個函式本身),兩個 story 的 commit 一起、依序推上 main,確保 main 的 `pnpm test` 任何時刻都是全綠,不會讓其他六條並行 lane 的 gate 因為一個跟他們無關的檔案而被拖紅。

## Assumptions / 計畫外事項
- `listActiveConversations()` 用 `pageSize:200`(contract 上限)模擬「不分頁、取全部」,因為 contract 沒有真正無上限的 list endpoint。MVP 規模下合理;若對話數超過 200,sidebar 歷史清單會截斷——記錄為已知限制,非本 story 需解決。
- Ajv 驗證刻意不註冊 `format:"uuid"`(只註冊 `date-time`),因為既有 `sidebar.test.tsx` 依賴的固定 seed id(`sample-1`/`sample-2`/`sample-3`)不是真正 UUID 格式,若強制檢查會讓每個回應都驗證失敗。`conversationId` 路徑參數改用手寫 regex 個別驗證(見 fake-api.ts),兩者互不影響。
- `apiClient` 測試用的 `baseUrl` 改成絕對值(`http://localhost/api/v1`),因為 Node 的 `fetch`/`Request` 不像瀏覽器會自動用「目前頁面」解析相對網址;production 仍用相對的 `/api/v1`(交給瀏覽器解析),見 `api.ts` 內的說明註解。
