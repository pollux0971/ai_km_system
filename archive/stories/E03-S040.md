## Assumptions / 計畫外事項
1. **TDD 順序的誠實偏離**:本 story 為了先確定「deps 要注入到什麼粒度才
   真的可測」,先寫了型別(`types.ts`)與實作(`errors/wav/resample/support/
   recorder.ts`)草稿,才寫測試,不是嚴格「先寫全部測試、再寫實作」的字面
   順序。但測試斷言完全依 spec 的 8 條 Functional AC 逐條撰寫,沒有回頭
   看實作細節來配合斷言;紅→綠的除錯過程中只修過**測試本身的技術性錯誤**
   (下面第 5 點),從未放寬或刪除任何 AC 相關斷言。記錄於此供 reviewer
   核實。
2. **`AudioWorkletNode` 追加為可注入 dep**:spec 技術決策只列了
   `getUserMedia`、`AudioContext`、`now()`、`setInterval` 四個可注入 deps,
   但真實瀏覽器建立 worklet node 必須呼叫全域 `new AudioWorkletNode(context,
   name)`,jsdom 沒有這個全域建構子。為了讓 `recorder.test.ts` 能在 jsdom
   下完整驅動狀態機(而不必依賴 `vi.stubGlobal` 硬替換全域建構子這種較脆弱
   的做法),`VoiceRecorderDeps` 多加了一個 `AudioWorkletNode` 建構子欄位,
   production 預設值是 `window.AudioWorkletNode`。這是內部實作細節的最小
   必要調整,不影響 spec 定義的公開 API 表面(`start`/`stop`/`onLevel`/
   `onStateChange`/`state`)。
3. **`onStateChange(cb)` 的 callback 簽名**:spec 只寫「`onStateChange(cb)`」
   未定義 `cb` 的參數。實作把它定為
   `cb(state: VoiceRecorderState, reason?: VoiceStopReason)`——`reason` 只在
   由 `stop()` 造成的轉換(`finalizing`/之後的 `idle`/`error`)才有值,其餘
   轉換(`idle→requesting→recording`)為 `undefined`。這是為了讓 AC2/AC3
   的「自動 stop 且 reason 為 silence/max_duration」可被測試觀察到——spec
   本身沒有另外定義任何「錄音完成」的通知管道,`stop()` 的回傳值又只有
   顯式呼叫 `stop()` 的呼叫方拿得到,自動觸發的 stop 沒有其他管道可觀察。
4. **TOO_SHORT 的傳遞方式**:spec 沒有明講 `stop()` 對 TOO_SHORT 是
   reject 還是回傳值裡帶錯誤。為與 `start()` 對其他五種錯誤一律用
   `reject(VoiceCaptureError)` 的模式一致,`stop()` 對 TOO_SHORT 也用
   reject,而不是把它塞進 `VoiceCapture` 的某個欄位。
5. **測試技術性修正**(依 STORY_WORKFLOW Phase 4 第 5 點的窄例外,誠實記錄):
   - `resample.test.ts` 原本斷言 `resampleLinear([0,1], 1, 2)` 長度為 3
     (誤以為是「頭尾+中點」的取樣點數公式),但實作(也是 AC1 驗證過、
     與 24000±48 精確吻合的)公式是 `round(length*toRate/fromRate)`,對這個
     輸入實際算出長度 4。判斷這是**測試本身算錯了取樣點數公式**(不是
     實作邏輯錯),改寫測試改用「首尾樣本值+單調遞增」而非硬編值斷言。
   - `wav.test.ts`/`recorder.test.ts` 原本用 `blob.arrayBuffer()` 讀回位元組,
     但 jsdom 的 `Blob` polyfill 沒有實作 `.arrayBuffer()`(已用一支獨立
     Node 腳本對 jsdom 直接驗證此限制)。判斷這是**測試環境 API 落差**
     (不是實作邏輯錯,`encodeWav` 本身回傳的仍是標準 `Blob`,瀏覽器/Node
     的 `Blob.arrayBuffer()` 都是原生支援),改用 jsdom 有支援的
     `FileReader.readAsArrayBuffer()` 包一層 Promise 讀回。
   - `recorder.test.ts` 的 AC2a/AC3 原本斷言在 `feedFrames`/`clock.advance`
     後同步檢查 `stateChanges` 是否已含 `["idle", reason]`,但自動觸發的
     `stop()` 內部 `await releaseResources()`(內含 `await
     audioContext.close()`)要跨過幾個 microtask 才會真正把狀態轉成
     `idle`,同步斷言時機太早。判斷這是**測試等待時機錯**(不是實作邏輯
     錯——`recorder.ts` 的狀態轉換本身是正確的,只是非同步),改用
     `await vi.waitFor(() => expect(recorder.state).toBe("idle"))` 等到狀態
     真的轉換完再斷言。
6. `apps/web/src/lib/voice/**` 內新增了測試用的 fake 型別（`FakeClock`、
   `FakeAudioContext`、`FakeAudioWorkletNode`）僅存在於 `recorder.test.ts`,
   未額外新增 production 檔案,符合允許修改清單。

「說完自動送出」流程)是第一個真的需要那份錄音的下游,才把這個既有缺口
逼出來。

修正純為新增(`onAutoStop` 是新方法,`stop()`/`start()`/VAD 邏輯/既有
callback 簽名全部未變),E03-S040 原本的 23 個測試零修改、rerun 仍全綠
(現為 28 個,含 E03-S041 新增的 5 個 `onAutoStop` 測試)。完整理由與嘗試
過的替代方案記錄於 `docs/stories/E03-S041.md`。
