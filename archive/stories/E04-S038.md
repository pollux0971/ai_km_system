## Contract / Migration 差異

**Contract:全部為新增,無既有 consumer,因此不構成 breaking change。**

相對於 apps/web 既有型別,**只新增兩個 server 產生的欄位**,兩者都在 spec 的

- `Conversation.updatedAt` —— E03-S039 需要分辨「重播到的事件」與「本地
  過期副本」。

`Conversation.archived` 在 contract 中是**必填**,apps/web 端是 `archived?`。
這不是形狀不相容:資料列一定有確定值,前端的 optional 只是為了讓
E03-S026 之前的 fixture 不必全部改;required 可指派給 optional,已由 AC2 的

### 全量回歸(含 E2E)——3 個既有 E2E flaky,非本 story 造成

`pnpm test` 預設會命中 turbo cache;審核時以 `pnpm test --force` 強制全量重跑,
發現它也會跑 `@ai-km/e2e`(264 個 E2E),其中 **3 個失敗**:

- `admin-e2e.spec.ts:53` — E11-S025 admin 首頁導覽
- `admin-analytics-e2e.spec.ts:44` — E13-S017 admin 首頁導覽(含延遲儀表板)
- `maintenance-e2e.spec.ts:84` — E07-S025 診斷歷程一致性

處理與判定(不是靠猜):

1. **隔離重跑全部通過** —— `playwright test <三支> --workers=1` → 3 passed。
2. **本 story 的 diff 不可能影響它們** —— 決定性檢查:對
   `tsconfig.json`／`.eslintrc*`／`vitest.config.*`／`playwright.config.*`／
   `next.config.*`／`turbo.json` 全域搜尋 `contracts`,**零命中**;
   `contracts/` 完全在所有 build／test graph 之外。本 story 的 diff 是
   1 個 yaml + 5 個 md + 2 個 ts(在 `contracts/openapi/__checks__/`,不被任何
   package include)+ 1 個 json,沒有一個檔案進得了 app 的建置或執行。
3. **已是登記在案的既有問題** —— `docs/architecture/tech-debt-audit-2026-08-28.md`
   第 4 點「已知會反覆發生但只用隔離重跑處理的 flaky」明列
   `E11-S019/S021/S022/S025`,正是其中之一;根因處理是 **E01-S027**
   (批次二,尚未開工)。

依 STORY_WORKFLOW 的誠實原則明說:**這 3 支在全量並行下是紅的**,我沒有
改動它們、沒有加 retries、沒有標 skip;它們的根因由 E01-S027 負責。

### redocly 的 2 個 warning(未抑制,誠實記錄)

`no-unused-components`:`ChangeEvent` 與 `ResyncEvent` 被判定為未使用。

原因是 OpenAPI **無法**為單一 SSE frame 的 body 定型——response body 是整條
原始字串串流,不是一個 JSON 物件。這兩個 schema 是每個 frame `data:` 行的
JSON 形狀,我以 vendor extension `x-sse-frame-payloads` 用 `$ref` 指向它們,
但 redocly 的該規則不追 extension 內的 `$ref`。

**沒有**用 `--generate-ignore-file` 把它蓋掉——那會讓下一個真正的未使用元件
也一起被靜音。AC1 要求的是「0 error」,已達成;這兩個 warning 是 OpenAPI
規格本身對 SSE 的表達力限制,不是 contract 的缺陷。codegen 仍會產出這兩個
型別(`components.schemas` 一律全數輸出),E03-S039 可直接使用。

### 既有問題:`core.yaml` 自身 lint 不過(非本 story 造成)

順手對 `core.yaml` 跑 lint 時發現它有 1 個 error:`no-empty-servers`
(「Servers must be present」)。已用 `git stash` 在**乾淨的 main** 上重跑確認
**完全相同**,且 `git diff main -- contracts/openapi/core.yaml` 為空——這是

## Assumptions / 計畫外事項

1. **`X-Client-Id` request header** —— 規格要求 `ChangeEvent` 有
   `originClientId?`,但沒有說 client 怎麼提供它。我定為由 mutating request
   的 `X-Client-Id` header 帶入,並在 spec 與事件文件明寫它是不受信任的 UX
   提示。這是把規格既有欄位補上唯一合理的來源,不是新能力;若 E03-S039 開發
   時 header 名稱要改,屬 non-breaking 調整。
2. **`GET /conversations/events` 與 `/conversations/{conversationId}` 並存** ——
   規格同時要求兩者。已在 spec description 說明:concrete path 優先,且
   `conversationId` 是 uuid,`events` 永遠不可能是合法 id,因此無歧義。
   redocly 未對此提出任何問題。
3. **`ResyncEvent.reason` 的枚舉值** —— 規格只寫 `data {reason}`,未列舉。
   我定為 `EVENT_LOG_TRUNCATED`／`UNKNOWN_LAST_EVENT_ID`／`SERVER_RESTART`
   三個,對應 ADR 0003 §7 描述得出的三種情境。E04-S044 實作時若需要第四種,
   新增枚舉值對 consumer 為 non-breaking。
4. **`content` / `attachmentNames` 的大小上限**(20000 字元 / 10 個附件 /
   單檔名 255 字元)—— 規格只要求 413 `PAYLOAD_TOO_LARGE` 存在,未給數字。
   Security Boundary 要求「對外輸入視為不可信:做 schema、size、type、range
   validation」,所以必須有具體數字才能被驗證;上述值為保守起點,E04-S042
   實作時可依實測調整(放寬為 non-breaking,收緊為 breaking)。
5. **lint 工具以 `pnpm dlx` 執行,未加進 devDependencies** —— 本 story 的允許
   修改清單不含 root `package.json`,故不新增依賴。指令已完整記錄於
   `contracts/openapi/__checks__/README.md`,reviewer 可原樣重跑。
6. **L2 gate 尚未進 CI** —— 同上理由(不能改 `turbo.json`／`package.json`)。
   **E03-S034**(codegen pipeline + drift gate)是擁有該項接線的 story,已在
   `__checks__/README.md` 與 `contracts/openapi/README.md` 兩處註明,不是被
   遺忘的 TODO。
7. **`info.license`** —— repo 沒有 LICENSE 檔也沒有 license 欄位,為消除
   redocly 的 `info-license` warning 填為 `UNLICENSED` /
   `LicenseRef-Proprietary`(企業內部系統)。若實際授權不同請告知修正。
