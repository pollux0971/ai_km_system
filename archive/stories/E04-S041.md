## Assumptions / 計畫外事項

1. **發現 `apps/api/src/server.ts` 的裝飾器順序問題(未修正,超出本 story 允許修改清單)**:`server.ts` 在 `await app.register(conversationPlugin)` 之後才呼叫 `app.decorate("contracts", contracts)`。Fastify 的 `register()` 會等待該 plugin 本體執行完成才 resolve,所以 `conversationPlugin` 執行時 `app.contracts` 尚未被裝飾,若在 route 註冊時同步呼叫 `app.contracts.getSchema(...)`(`apps/api/README.md` 規則 #3 建議的做法)會擲出 `TypeError`。`server.ts` 不在本 story 允許修改清單內(允許修改僅 `services/conversation/**`、`db/seeds/**`),故未修正該檔;改為將 `CreateConversationRequest`/`UpdateConversationRequest` 的 JSON Schema 逐字轉寫進 `routes/conversations.ts`(與 query schema 已經是同樣做法),並以 `testing/contract-check.ts` 對每個 endpoint 的每個狀態碼做回應層的契約驗證來補償。建議另立一個小 story(或在 E04-S042/S043 一併)修正 `server.ts` 的裝飾器順序。
2. **`plugin-types.ts` 刻意不使用 `declare module "fastify"` ambient augmentation**:因為 `@ai-km/service-conversation` 的 `package.json` 把 `main`/`types` 指向本 package 的 TypeScript 原始碼(而非預先編譯的 `.d.ts`),`apps/api` 的 `tsc` 執行會直接型別檢查這些原始碼。若在此宣告與 `apps/api/src/types.ts`/`contracts.ts` 不同形狀的同名全域擴充(`contracts`、`request.auth`),兩邊被同一次編譯同時看到時會產生 TypeScript 的「後續屬性宣告型別不一致」錯誤。改用檔案內說明的窄型別 cast 存取,已以 `pnpm --filter @ai-km/api typecheck`(0)與 `pnpm --filter @ai-km/service-conversation typecheck`(0)兩邊分別驗證不衝突。
3. **PATCH 空物件視為真正的 no-op**:契約文字「Sending an empty object is a no-op update and still returns the current conversation」沒有明確排除 empty-object 是否仍寫入 `updatedAt`/`change_events`。本實作選擇：完全不寫入(不動 `updatedAt`、不送 `conversation.updated` 事件),因為這最符合「no-op」的字面意思,且此路徑沒有對應的 Functional AC 明確要求相反行為。已用測試 `"an empty body is a no-op that still returns the current conversation"` 鎖定此行為,供未來 reviewer 確認是否需要調整。
4. **PATCH `mode` 未指定時的預設值**:`CreateConversationRequest.mode` 在契約中未列出 `default:`。依 `apps/web/src/lib/conversations.ts` 現有前端行為(建立對話一律 `mode: "normal"`)及 spec 對 POST 預設值段落的隱含語意,實作預設為 `"normal"`。
5. **domain 層錯誤未使用 `ApiHttpError` 類別**:`ConversationDomainError`(本 package 自訂)在真實 `apps/api` 錯誤處理器中會走通用 fallback 分支(依 `statusCode` 對應到正確的 `code`,但訊息文字是通用訊息而非本 story spec 建議的特定中文句子,例如 403 訊息會是「沒有執行這個操作的權限。」而非 spec 建議的「沒有存取這筆對話的權限。」)。契約只要求 `message: string`,不鎖定字面文字,故此為 schema-合規、僅措辭不同的已知取捨,已在 smoke 測試輸出中如實記錄。
6. **未跑整個 monorepo 的 `pnpm test`**:root-level `pnpm test` 會牽動 `apps/web`/`apps/admin`(vitest,量體很大,多個 lane 同時佔用 8 核心會使其變慢,非 hang,但完整跑完超過可接受等待時間)。本 story 未修改這兩個套件,且 Turbo 的 cache 機制在其輸入未變時本來就會 cache-hit;改為對受影響套件(`@ai-km/service-conversation`、`@ai-km/api`)分別執行 typecheck/lint/test,以及對整個 repo 執行 `pnpm typecheck`/`pnpm lint`(皆為 23/23 全綠、非長時間任務)。E2E(Playwright)未跑,原因見上方 Gate 紀錄。
