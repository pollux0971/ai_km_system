# E09-S005 — Query confirmation UI

- Branch: `story/E09-S005-query-confirmation-ui`
- Date: 2026-08-16
- Status: DONE

## Scope 說明

E09 的第五個 story,在「選擇查詢情境」(S003/S004)與「執行查詢」
(S006「Query loading state」,尚不存在)之間插入一個明確的確認關卡
——使用者必須主動點擊「確認執行查詢」,查詢才算準備好交給 S006 執行。

## 設計決策

**確認是獨立的按鈕點擊,不是選擇情境的附帶動作**:曾經考慮讓
「選擇情境」與「確認」合併成一次點擊(選情境 = 自動確認),但這樣
「Query confirmation UI」作為一個獨立 story 就沒有實質內容——這個
story 存在的理由,正是要有一個明確、獨立的「執行意圖」手勢,不能與
選擇動作合併。因此設計為:選擇情境後,`erpQuery.selectedScenarioId`
已存在但 `confirmedAt` 尚未存在時,顯示「查詢情境:{label}」+ 一個
新的「確認執行查詢」按鈕;點擊後呼叫新的 `confirmErpQuery`,記錄
`confirmedAt` 時間戳記(鏡射 `createdAt` 自己「記錄何時,不只記錄是否」
的既有慣例,而非用布林值)。

**三個既有測試需要「範圍收斂」而非修改語意——誠實記錄,判斷依據見下**:
S003/S004 各有測試斷言「選擇情境後,main 內(或整個畫面)沒有任何
button」(`erp-query-detail.test.tsx` 兩處 `expect(screen.queryAllByRole
("button")).toHaveLength(0);`,`erp-home.spec.ts` 一處
`getByRole("main").getByRole("button")).toHaveCount(0)`)。這些斷言在
撰寫當下完全正確(選擇後畫面上真的沒有任何按鈕),但本 story 在
「選擇之後、確認之前」這個時間點合法地新增了一個按鈕(用途完全不同:
不是挑選情境,是確認執行意圖)。

判斷這屬於 Phase 4 第 5 點以外、但同樣有本 session 既有前例的情況
(E07-S024 對 E07-S002/E07-S005 兩個既有測試加 `exact: true` 的處理
方式,理由記錄在 `docs/stories/E07-S024.md`):不是「測試寫錯」,而是
「測試當初用了比它實際想驗證的範圍更廣的 locator(`queryAllByRole
("button")` 抓的是『所有按鈕』,但測試自己的描述與意圖明顯是『情境
picker 自己的按鈕消失了』)」,後續合法新增的、用途不同的按鈕讓這個
過廣的 locator 意外連坐。修正方式是把斷言收斂到「情境 picker 自己的
按鈕(以各情境的 label 命名)確實消失」,而不是「畫面上任何按鈕都不能
存在」——這與斷言原本的文字描述("shows the selected label instead of
the picker"、"with no picker")完全吻合,只是原本的 locator 選得太寬。
斷言的可觀察行為(picker 消失)語意完全未變,只有 locator 精確度提高。

三處修正:
1. `erp-query-detail.test.tsx`「selecting a scenario calls...」測試:
   `queryAllByRole("button")).toHaveLength(0)` → 逐一確認每個情境
   label 對應的 button 已消失。
2. `erp-query-detail.test.tsx`「shows the already-selected scenario...」
   測試:同上收斂。
3. `erp-home.spec.ts` S002 延伸測試:同樣收斂為逐一檢查 4 個情境 label
   按鈕已消失,**新增**(非修改)一個全新斷言在確認之後(不是修改前）
   驗證「確認後,main 內真的零按鈕」——這個新斷言本身是本 story 自己
   新增的合法內容,驗證確認流程走完後畫面確實乾淨。

**`erp-queries.ts` 的 `confirmErpQuery` 鏡射 `selectErpQueryScenario`
既有形狀**:NOT_FOUND(未知 id)/ VALIDATION_ERROR(尚未選擇情境就
確認)。伺服端驗證即使按鈕只在選擇後才出現,同一貫「不信任被繞過的
client」紀律。
