## 設計決策

### 只建模一個真實存在的設定,不發明其他設定項目

`AI_KM_BMAD_High_Granularity/` 全文與 `docs/stories/PROGRESS.md`/`TRACEABILITY.md` 對「System settings」這個 story title 都沒有更具體的規格內容(story 章節本身是與其他每個 E11 story 完全相同的通用範本,無 story 特定細節)。為了不發明未定義的設定項目,本 story 先在整個 codebase 中搜尋「這個系統目前真的有哪些全域、Team A 自己擁有、已核准的設定值」——結果只有一個:`apps/web` 自己的 `lib/feature-flags.ts`(E01-S015,已核准)的 SSO feature flag,`FLAGS.sso.defaultEnabled: true`。除此之外,`apps/web`/`packages/` 全域沒有任何其他「setting」概念。

因此本 story 刻意只建模這一個真實存在的設定,不為了讓頁面看起來更豐富而發明額外的假設定項目——比照 Department/Group(S009/S010)當年「只用已存在於別處的真實值,不發明業務內容」的判斷。

### 鏡射真實值,不是直連 apps/web 的執行狀態

`ssoEnabled` 的初始值 `true` 直接取自 `feature-flags.ts` 的 `defaultEnabled`,但這是**鏡射**,不是**匯入**——`apps/admin` 與 `apps/web` 是兩個獨立部署的 Next.js app,各自的執行狀態(包含 `process.env` 與瀏覽器儲存)互不相通,這與 `models.ts`(E11-S013)已經記錄的邊界完全相同。因此在 admin 端切換這個設定,是一個純粹的本地 sessionStorage mock 動作,對 `apps/web` 真正讀取的 `process.env.NEXT_PUBLIC_FEATURE_SSO` 沒有任何真實影響——與 Model/Connector 的 enable/disable(S013/S014)是同一種誠實揭露的「零真實效果」mock 動作,第三次沿用同一個判斷框架。

### 沒有 empty 狀態

因為系統只有一個設定(不是清單),UI 只有 loading/error/loaded 三態,沒有像 User/Model/Connector 清單那樣的 empty 狀態——這不是遺漏,是因為「一個全域設定物件永遠存在」這件事本身沒有「空」的概念。

**FIX 循環 1 次**:第一輪 unit test 執行時,`system-settings-panel.test.tsx` 的 5 個測試失敗——根因是 `<p><strong>SSO 登入</strong>：{ssoEnabled ? "已啟用" : "已停用"}</p>` 把狀態文字與其他文字串接在同一個 `<p>` 內、同一個文字節點層級,導致 `screen.findByText("已啟用")` 找不到獨立可查詢的元素(RTL 的文字比對是以「元素自身文字內容」為單位,一個 `<p>` 裡混雜 `<strong>` 子元素 + 純文字節點時,沒有任何單一元素的 textContent 恰好等於 "已啟用")。判定為真實實作缺陷(UI 結構問題,非測試寫錯),修正為拆成兩個獨立 `<p>`(比照 `user-list.tsx` 的 `<p>{STATUS_LABEL[user.status]}</p>` 既有慣例,狀態文字永遠獨立成自己的元素)。修正後從 VERIFY 第一個 gate(typecheck)重新開始,全數重跑皆綠。

## 對抗性自我驗證(SELF-REVIEW)

目標:證明切換方向邏輯真的依目前狀態呼叫對應的函式,不會恆定呼叫同一個。

突變:把 `handleToggle` 的 `state.settings.ssoEnabled ? await disableSso() : await enableSso()` 改成恆定呼叫 `await enableSso()`。

結果:精準命中 2 個測試——「clicking 停用 calls disableSso (not enableSso)...」(mock 的 `disableSso` 未被呼叫,`enableSso` 未設定回傳值導致 `result` 為 `undefined`,讀取 `result.ok` 拋出例外)、「shows a distinct error message and keeps the current state when toggling fails」(同樣因為呼叫了未設定回傳值的 `enableSso` 而非已設定失敗回傳值的 `disableSso`)。其餘 5 個測試不受影響。

已用 `git checkout --` 還原突變(先前已用 `git add -A` 建立 checkpoint),重新執行 admin 全部單元測試(37/37 檔案 271/271 tests)確認全綠。
