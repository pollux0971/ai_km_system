### Security / Authorization

| AC | 驗證 |
|---|---|
| 需登入 | document-level `security: [sessionCookie]` + operation 繼承;scheme `$ref` 自 auth.yaml(已實測解析) |
| spec 明文不保存音檔、不記文字 | `info.description` 有**專段**寫明:音檔只在請求期間存在,不落地、不進 log、不進 telemetry/audit;telemetry 只記時長／字數／耗時／provider／model,**辨識文字永不記錄**,並說明理由(那是使用者職場的談話內容,log 裡的逐字稿與資料庫裡的逐字稿是同一種洩漏,而且沒有任何存取控制) |

補充(規格未明列,屬 Security / Failure Boundary):
- `conversationId` 的 description 明文寫它**不是授權輸入**——端點不檢查
  caller 是否擁有該對話、也不因它改變行為,所以填別人的 id 得不到任何東西。
  這避免了它日後被誤當成授權依據。
- 503 `ASR_UNAVAILABLE` 的 description 明文 **fail closed**:sidecar 不可達
  時**不會**靜默改送雲端 provider、**不會**回傳佔位文字,前端退回鍵盤輸入。
  這正是 Failure Boundary 的「Model failure 不得靜默切換至未核准 provider」。
- `provider: fake` 的 description 明文「只在明確設定時啟用,且 `fake` 結果
  不得當作整合證據」——把 TESTING_POLICY 的規則寫進契約本身。

## Assumptions / 計畫外事項

1. **未新增 `__checks__` 型別相容檔** —— 允許修改清單只有 yaml 與 README。
   AC3 只要求「型別可由 codegen 產生且欄位齊全」,已用實際輸出佐證。
   若日後要把 transcriptions 也納入常設的相容性 gate,應併入
   **E03-S034**(codegen pipeline + drift gate)。
2. **`securitySchemes` 採 `$ref`** —— 規格允許兩種寫法,因 E02-S031 已合併
   而採 `$ref`(已記錄於上)。
3. **`encoding.audio.contentType: audio/wav`** —— 規格說 `audio`(binary,
   `audio/wav`)。OpenAPI 表達「某個 multipart part 的內容型別」的正式位置是
   `encoding`,而非 schema 內,故寫在那裡。
4. **30 秒 ASR 逾時、4 MiB、60 秒上限** —— 皆為規格與 ADR 0004 明訂的數字,
   非我自訂。
5. **`AUDIO_TOO_SHORT` 的門檻未寫進 contract** —— 規格只列出這個 reason,
   沒給毫秒數。門檻屬實作細節(E12-S031),寫進契約反而會讓調整變成
   breaking change。
