## 現況盤點與架構張力判斷(Scope 判斷的依據)

`AI_KM_BMAD_High_Granularity/epics/E13_Feedback_&_Analytics.md` 的 E13-S012 章節逐字比對確認是泛用樣板文字,無 story 專屬內容。`contracts/` 逐字搜尋零 usage/dau/analytics 相關內容。

已核准的 `apps/admin/src/lib/usage-metrics.ts`(E11-S021)doc comment 明確點名:「真正的資料來源是 `E13-S009` 事件埋點 / `E13-S010` 對話分析事件,feeding `E13-S012` DAU/questions dashboard——this story's own direct real-data source」。E13-S009/S010/S011 皆已 approved,在 `apps/web/src/lib/usage-events.ts` 建立了完整的事件持久化(`recordUsageEvent`/`listUsageEvents`),記錄 `conversation_message_sent`/`conversation_created`/`rag_answer_outcome` 三種事件,並在各自的 EVIDENCE 裡明確記錄「彙總邏輯留給 E13-S012」。

**本 story 面對的架構張力**:`apps/admin`(E11-S021 已建的 Usage dashboard UI)與 `apps/web`(真正擁有 usage-events 資料的地方)是兩個獨立 Next.js app,這個 codebase 沒有真正的後端 API server,`sessionStorage` 是各自 origin 獨立。這跟 Feedback 系列(E11-S016/S017、E13-S007/S008)面對的情況完全同構——那一系列的解法是:admin 端的 `listFeedback()`/`getFeedback()` 誠實維持永遠空/null,不偽造跨 app 資料。E11-S021 已經對 Usage 走過同一條路:`getUsageMetrics()` 永遠回傳 `{ 0, 0 }`,並已經建好完整的 loading/error/loaded 三態 dashboard UI、首頁入口連結。

**兩條可能路徑的取捨**:
1. 在 `apps/admin` 把 dashboard 接上「真實」資料——技術上做不到(除非偽造跨 app 資料管道,違反已建立的紅線),而且 E11-S021 已經把「顯示誠實零計數 + 說明文字」這件事做完了,若本 story 只是重做 E11-S021 已完成的東西,沒有新價值,純屬重複勞動。
2. 在 `apps/web`(真正擁有資料的地方)建立 `computeDAU`/`computeQuestionsAsked` 彙總純函式,用真實記錄的 usage-events 完整測試證明彙總邏輯本身正確——這才是 S009/S010/S011 三個 story 反覆說「彙總留給 S012」時,真正尚未完成的那塊拼圖。這不等於「apps/admin dashboard 顯示真實數字」這個更大目標已經達成(那仍然卡在缺少真實跨 app 後端這個既定架構限制,需要 Team B 提供真實 API 才能完全串接),但這是本 story 誠實能交付、且真正未被任何既有 story 做過的價值。

**判斷:選路徑 2。DONE,非 BLOCKED**——因為即使無法達成「dashboard 顯示真實數字」這個字面意義的完整目標,彙總邏輯本身的正確性是可以被誠實證明的、有真實價值的產出,不屬於「重複勞動」或「造假綠燈」。誠實記錄:本 story 完成後,`apps/admin` 的 `usage-metrics.ts`/`getUsageMetrics()` 依然完全未觸碰,依然誠實回傳零計數——那個更大的目標仍待 Team B 提供真實 API。

## Assumptions / 計畫外事項

- **架構限制的誠實延續**:`apps/admin` 的 `getUsageMetrics()` 依然完全未觸碰,依然誠實回傳零計數。本 story 完成不代表 Usage dashboard 已經顯示真實數字——這個更大目標需要 Team B 提供真實跨 app API(或後端持久層)才能完全串接,已在 EVIDENCE 誠實記錄,不隱藏這個限制。
- `computeDAU` 的曆日邊界採 UTC 曆日(`occurredAt.slice(0, 10)`),不是 rolling 24 小時窗口——比照這個 codebase 既有的 UTC storage 慣例(`occurredAt` 本身已是 ISO/UTC timestamp),給出穩定、無歧義的「今天」邊界定義,這是本 story 自己的判斷,非 baseline 明文規定。
- `computeQuestionsAsked` 計算的是事件總數(每次真實送出各計 1),不是去重使用者數——對應 E11-S021 EVIDENCE 裡「questionsAsked」這個指標名稱本身的字面意涵(提問「次數」,非提問「人數」),與 `computeDAU`(去重使用者數)的語意刻意區分。
