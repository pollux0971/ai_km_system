# E01-S032 — `web:build` 與 e2e webServer 的 `next dev` 競寫 `.next`,完整 `pnpm test` 無法跑完

## Metadata
- Epic: E01 Application Shell & User Workspace
- Owner: Team A(W7,`tests/e2e` 與 `turbo.json` 的近期修改者)
- MVP: **Required — 每個 story 的 L1 gate「`pnpm test` 全綠」目前都無法完成**
- Story size target: 0.25 developer-day

## 問題陳述(總指揮已驗證機制)
```
tests/e2e/package.json   dependencies: ["@ai-km/auth-client"]   ← 沒有 web / admin
turbo.json               test.dependsOn: ["^build", "build", "check"]
tests/e2e/playwright.config.ts:110   command: "pnpm --filter @ai-km/web dev"
```
`^build` 只排序**已宣告依賴**的 build。`@ai-km/e2e` 沒有把 `@ai-km/web`/
`@ai-km/admin` 列為依賴,所以 turbo **不會**把 `@ai-km/web:build` 排在
`@ai-km/e2e:test` 之前——兩者並行執行,而:

- `@ai-km/web:build` 跑 `next build` → 寫 `apps/web/.next`
- e2e 的 webServer 跑 `next dev` → **同時**寫 `apps/web/.next`

結果是 `Cannot find module './315.js'` / `PageNotFoundError`,而且**每次指向
不同頁面**(`/citations/[id]`、`/icon.svg`、`/conversations/new`)——這正是
競爭而非快取損毀的特徵。W4 已 `rm -rf apps/web/.next apps/admin/.next` 後
原樣重現,排除快取損毀。

**影響**:任何人跑完整 `pnpm test` 都可能中途炸掉,而 STORY_WORKFLOW 的 L1
gate 正是 `pnpm test`。目前各 lane 只能用 `--filter` 繞開,拿不到一次完整綠燈。

## Scope In
- 讓 `@ai-km/web:build` / `@ai-km/admin:build` 與 e2e 的 webServer **不再並行
  競寫同一個 `.next`**。方式由開發者判斷並在 EVIDENCE 說明取捨,建議最小改動:
  在 `tests/e2e/package.json` 把 `@ai-km/web`、`@ai-km/admin` 宣告為
  devDependency,讓 turbo 的 `^build` 自然把它們排在前面。
- 新增驗證:連續跑兩次完整 `pnpm test`,兩次都不出現 `PageNotFoundError` /
  `Cannot find module './<chunk>.js'`。

## Scope Out
- 不改 `playwright.config.ts` 的 webServer 指令(改成 `next build && next start`
  是更大的變更,屬別的 story)。
- 不改任何 `apps/*/src` 的 production 程式碼。
- 不改既有測試內容。

## 依賴關係
- HARD 依賴:無(E01-S027 已把 `test.dependsOn` 加上同套件 `build`,本 story
  補的是**跨套件**的排序)。
- **下游**:所有 story 的 L1 gate。

## Functional Acceptance Criteria
1. 連續兩次完整 `pnpm test` 都跑完,無 `PageNotFoundError` / 模組找不到。
2. **反向驗證**:暫時還原設定,確認能重現原本的競爭錯誤(或說明為何無法穩定
   重現、改以 turbo 的任務圖輸出證明排序確實改變)。
3. 既有測試零修改且全綠。
4. 記錄兩次跑的耗時與 `uptime`——若新增的排序讓總時間顯著變長,要說明。

  只是降低命中率。
