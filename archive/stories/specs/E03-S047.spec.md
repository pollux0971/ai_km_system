# E03-S047 — `send-message.spec.ts` 的預覽測試,**只有在它要驗的行為沒發生時才會通過**

## Metadata
- Epic: E03
- Owner: Team A(`ai-km-2c`,發現者,握有重現條件)
- MVP: **Required — 擋住 E01-S022 的 AC4「全綠」**
- Story size target: 0.25 developer-day

## 問題陳述(已重現,非負載雜訊)

`ai-km-2c` 在**安靜機器**(load 11.97 → 10.63)上對這支測試單獨跑
`--repeat-each=3`:**12 個實例、2 個失敗、10 個通過**,兩次失敗訊息逐字相同:

```
strict mode violation: getByText('這則會成為新的預覽文字') resolved to 2 elements
  1) sidebar 的 <p class="sidebar-history-preview">
  2) main 裡的 <span>(訊息串本身的內容)
```

§5-ter 三個條件全部滿足,**這是真缺陷,不是 flaky**。

### 根因:斷言沒有 scope,同時命中側欄與主畫面

```ts
tests/e2e/specs/send-message.spec.ts
test("E03-S009: sending a message updates the conversation list's preview", ...)
  await page.getByLabel("訊息").fill("這則會成為新的預覽文字");
  await page.getByRole("button", { name: "送出" }).click();
  await expect(page.getByText("這則會成為新的預覽文字")).toBeVisible();   // ← 失敗點
  ...
  await sidebarNav(page).getByRole("link", { name: "對話" }).click();
  await page.waitForURL(url => url.pathname === "/conversations");
  await expect(page.getByText("這則會成為新的預覽文字")).toBeVisible();   // ← 同樣未 scope
```

`sidebar.tsx:119` 會把 `conversation.lastMessagePreview` 渲染成
`<p class="sidebar-history-preview">`。送出訊息後,**側欄預覽與主訊息串
兩處都有同一段文字**,未 scope 的 `getByText` 於是命中 2 個元素。

### ⚠️ 最重要的一點:這支測試**通過的時候才是壞的**

失敗率是 2/3 而非 3/3,因為它是一場競速:

- 側欄預覽**還沒**更新 → 只有 1 個命中 → **通過**
- 側欄預覽**已經**更新 → 2 個命中 → strict mode violation → 失敗

而這支測試的名字是「**sending a message updates the conversation list's preview**」。

**它在「預覽尚未更新」時通過,在「預覽已經更新」時失敗——語意完全顛倒。**
它從來沒有真的驗證過它宣稱要驗證的行為;它偶爾變綠只是因為它搶在功能生效
之前就斷言完了。這跟 `smoke.spec.ts` 的 route-announcer 碰撞是同一族
(未 scope 的 `getByText` 同時命中兩個區塊),但後果更嚴重——那個只是誤報,
這個是**測試意圖的反轉**。

## Scope In
只修 `tests/e2e/specs/send-message.spec.ts` 裡未 scope 的 `getByText` 斷言。

## Scope Out
- **不改任何 production 程式碼**。`sidebar.tsx:119` 渲染預覽是**正確行為**
  (E03-S009 的功能本身),不是缺陷。
- 不動其他 spec 檔;若發現同族問題,回報總指揮另案處理,不順手改。
- 不改測試的**意圖**——不得為了讓它變綠而刪掉任何一個斷言。

## Functional Acceptance Criteria

- **AC1**:兩個 `getByText` 斷言都加上 scope,且**分別 scope 到它各自
  真正要驗的區塊**:
  - 送出後的第一個斷言 → 驗的是**訊息串**收到訊息(`getByRole("main")` 或
    訊息串本身的 landmark)。
  - 導覽到 `/conversations` 後的第二個斷言 → 驗的是**對話列表的預覽**
    (測試名所指的東西)。
  ⚠️ **不得把兩個都籠統 scope 到同一個容器就算完事**——要能說明每一個
  斷言現在驗的是哪一個區塊,寫進 EVIDENCE。
- **AC2(反向驗證,強制)**:
  1. 貼出**修正前**在安靜機器上 `--repeat-each=3` 的實際輸出(重現失敗)。
  2. 貼出**修正後**同樣條件 `--repeat-each=3` 的輸出,**12/12 全過**。
  單跑一次通過不算——這支測試本來就有 1/3 機率通過。
- **AC3(非空洞性)**:證明修正後的斷言**真的會因為功能壞掉而變紅**。
  最簡單的做法:暫時把斷言的文字改成一個不存在的字串,確認它失敗,再改回。
  貼出輸出。**否則無法區分「修好了」與「換成了一個永遠通過的斷言」。**
- **AC4**:`send-message.spec.ts` 其餘測試零回歸(同檔其他 3 支全過)。
