# E04-S049 — `apps/api` bootstrap 順序修正:`app.contracts` 必須在 route 註冊前可用

## Metadata
- Epic: E04 RAG & Conversation Intelligence(使用者增補追蹤範圍)
- Owner: Team A(使用者 2026-08-28 裁示新增並指派)
- MVP: Required(阻擋後續所有新增 apps/api route 的 story 使用 contract schema)
- Story size target: 0.25–0.5 developer-day
- Story 來源: E04-S041 EVIDENCE 記錄的發現 + 使用者 2026-08-28 裁示

## 問題陳述
`apps/api/src/server.ts` 目前的 `await app.register(conversationPlugin)`
排在 `app.decorate("contracts", ...)` **之前**。Fastify 的 plugin 在註冊階段
會同步執行 route 定義,若 route 定義中呼叫 `app.contracts.getSchema()`,
此時 `app.contracts` 尚未被裝飾,會丟出 TypeError。

後果:每個新增 route 的 story 都必須改用「逐字轉寫 JSON Schema」繞過
(E04-S041 已如此處理並記錄)。逐字轉寫的 schema 與 `contracts/openapi/`
之間**沒有機器檢查**,是 contract drift 的溫床——正是 E03-S034 建立
drift gate 想防止的東西。

## Scope In
- 調整 `apps/api/src/server.ts` 的 bootstrap 順序,使所有 `app.decorate(...)`
  在任何 `app.register(<route plugin>)` 之前完成。
- 新增迴歸測試:**route 註冊階段呼叫 `app.contracts.getSchema()` 不得拋錯**。
  此測試必須在修正前為紅、修正後為綠(EVIDENCE 需記錄修正前的紅燈輸出)。

## Scope Out
- 不改任何既有 route 的行為、路徑、回應 schema。
- **不回頭把 E04-S041 已逐字轉寫的 schema 改回 `getSchema()`**——那屬於
  該 story 的範圍,由後續 story 或 E04-S041 的後續維護處理。
- 不新增/修改任何 contract yaml。
- 不改 `services/*`、`db/*`、`apps/web`、`apps/admin`。

## 依賴關係
- HARD 依賴 Story:E04-S039(api bootstrap,已 approved)、E04-S041
  (問題發現來源,已 approved)。
- 下游 Story:E04-S042、E04-S043、E04-S044、E04-S047、E04-S048、
  E02-S033、E02-S034、E12-S031 — 皆因此不必再逐字轉寫。

1. Given 一個在 route 定義階段呼叫 `app.contracts.getSchema()` 的
   測試用 plugin,When `buildServer()` 註冊它,Then 不拋錯且 server 正常啟動。
2. 修正前該測試為紅(TypeError),修正後為綠;EVIDENCE 需附修正前後兩段輸出。
3. `apps/api` 既有 90 個 unit test **零修改**且全綠。
4. `services/conversation` 既有 98 個測試零修改且全綠(E04-S041 的繞道寫法
   不因本次修正而失效)。
