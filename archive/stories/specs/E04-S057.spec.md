# E04-S057 — repo 根目錄的 `pnpm test` 會無鎖跑全量 E2E,可污染別人持鎖中的量測

## Metadata
- Epic: E04(使用者增補追蹤範圍)
- Owner: Team A(W4,缺陷揭露者,已有完整脈絡)
- MVP: **Required — 已實際造成一次證據污染**
- Story size target: 0.5 developer-day

## 問題陳述(已查證)

```
turbo.json:18
  "test": { "dependsOn": ["^build", "build", "check"] }

tests/e2e/package.json:9
  "test": "playwright test"          ← 完全不知道 .e2e.lock 存在
```

**`pnpm test` 在 repo 根目錄執行時,turbo 會把 `@ai-km/e2e:test` 一起跑進去,
而它就是完整的 `playwright test`,沒有任何鎖協調。**

再加上 `helpers/port-check.ts:18` 的 `resolveReuseExistingServer()` 回
`!process.env.CI`(本機恆為 `true`),這個無鎖的 Playwright **會直接沿用
持鎖者已經起好的 :3000/:3001 dev server**,兩份測試同時打同一組 server。

### 已造成的實際損害(2026-08-29 07:2x)

- W1 持 `.e2e.lock` 跑 E01-S022 的全量 E2E 重跑——**那次重跑是該 story 被
  降級後唯一的補救措施**。
- W4 在不知情下於 repo 根目錄跑了 `pnpm test`,turbo 連帶啟動 `@ai-km/e2e:test`。
- W4 誠實揭露:**沒有保留該 e2e task 的 webServer log,無法排除它真的
  `reuseExistingServer` 接上了 W1 的 dev server。**
- W1 的那次跑到 133/271 時,最後 9 個測試裡 6 個逾時,已判定資料污染並中止。

**沒有人違規**——`pnpm test` 是最自然的全量驗證指令,沒有任何東西告訴使用者
它會碰 E2E。這是基礎設施缺陷,不是人的錯誤。

## Scope In
1. 讓「沒有持鎖卻要跑 E2E」這件事**大聲失敗**,而不是靜默污染別人的量測。
2. 涵蓋**所有入口**,不只 `pnpm test`:直接 `playwright test`、
   `--last-failed`、`--project=...`、turbo 間接觸發,全部要被擋。

## Scope Out
- 不改 `.e2e.lock` 的取得/釋放機制本身(§5 的既有協定不動)。
- 不把 `@ai-km/e2e` 從 turbo 的 `test` pipeline 移除**作為唯一解**——
  那會讓 `pnpm test` 從此不再涵蓋 E2E,是把問題藏起來而不是修掉。
  (要移除可以,但必須同時提供一個明確的、有鎖保護的全量入口。)

## 建議做法(實作者可自行判斷,理由寫進 EVIDENCE)

在 `playwright.config.ts` 的 **module-eval 階段**做檢查——該檔已經在那個
時機跑 `ensureFakeMicrophoneWav()` 與 `assertPortsFreeForCI()`,是既有慣例,
而且**它涵蓋所有入口**(不管是誰、用什麼指令觸發 Playwright 都會經過)。

判定邏輯:

```
讀 /data/python/AI_KM-worktrees/.e2e.owner
  - 檔案不存在        → 沒人持鎖,放行
  - 內容 == 自己       → 我就是持鎖者,放行
  - 內容 == 別人       → 立刻 throw,訊息要指名「現在是誰持鎖」
```

「自己是誰」需要 flock wrapper 傳進來(例如 wrapper 寫 `.e2e.owner` 的同時
`export` 一個同值的環境變數)。**wrapper 那側的改動要一併做,否則持鎖者
自己會被自己擋住**——這一點務必實測。

## Functional Acceptance Criteria
- **AC1**:`.e2e.owner` 指向別人時,於 repo 根目錄跑 `pnpm test`,
  `@ai-km/e2e:test` **明確失敗並指名持鎖者**,不得靜默跑起來。
- **AC2**:`.e2e.owner` 指向別人時,直接跑 `pnpm exec playwright test`
  與 `pnpm exec playwright test --last-failed` **同樣被擋**。
- **AC3(最容易做壞的一條)**:**持鎖者自己必須能跑。** 實際取一次鎖、
  在鎖內跑一次 E2E(哪怕只跑一支 spec),證明沒有把自己擋掉。
- **AC4**:`.e2e.owner` 不存在時,一切照舊可跑(不得變成「一定要先取鎖」)。
- **AC5(反向驗證,強制)**:AC1/AC2 都要附上**修正前**的實際輸出
  ——證明修正前它真的會跑起來——再附修正後被擋的輸出。
- **AC6**:`pnpm test` 仍然涵蓋 E2E(或提供等價的、有鎖保護的全量入口,
  並在 README/ROADMAP 寫明)。不得靠「把 E2E 從 pipeline 拿掉」了事。

## Security / Authorization Acceptance
不適用(純測試基礎設施)。但**不得**用 `|| true`、`--passWithNoTests`
或任何讓 E2E 靜默跳過的方式達成 AC1——擋下來要是**明確失敗**,不是靜默略過。
