# ADR 0012: 開發卡住時由技術顧問裁決,不回到使用者

Status: Accepted(2026-09-04,使用者在協調者 session 直接指示)

## Context

`CLAUDE.md`「決策權」段把七類事情保留給使用者:契約放寬、新 endpoint / schema、刪欄位、
請求側收緊、新資料夾或 Team B 路徑授權、付費與外部服務、真模型選型、以前沒提過的功能與
產品行為未定義、整合點 `@e2e` 驗收。

2026-09-04 的回填一輪就翻出九條落在這些類別裡的問題(`DECISIONS_NEEDED.md` #7–#15)。
其中 #7(E04-S009 的四題:部門顯示名與 store 鑰匙的對應、群組算不算一把鑰匙、部門與群組
是聯集還交集、跨部門搬過去的文件原部門還看不看得到)**直接擋住** `02-authorization`
的 phase-2,連帶擋住 I3;#8 與 #10(knowledge 契約不存在、`Message` 沒有 citations 欄位)
擋住 I2 的最後一塊。

依原本的規則,協調者只能把它們寫進收件匣、繼續做別的。但回填做完之後,「別的」快要用完了:
剩下的工作大多要穿過這幾道 gate。

## Decision

**使用者 2026-09-04 在協調者 session 原話:「如果有問題,或是開發過程卡住,以技術顧問建議
為主不需要我的裁決」。**

自即日起:

- **當一件事正在擋住開發**(某個 phase 沒有它就一行都不能寫、某個整合點沒有它到不了),
  即使它落在「決策權」表原本保留給使用者的類別裡,**由技術顧問(ai-km-3a 系列)裁決,
  協調者照辦,不等使用者**。裁決以 ADR 留痕,commit 引用。
- 顧問不在時,協調者自己定並記 ADR(這一條與原表「工程取捨」列一致)。
- **仍然回到使用者的**:`@e2e` 整合點驗收(使用者親手,不可代——這是 GHERKIN_WORKFLOW §5.4
  的核心,不是「卡住」能覆蓋的);以及**修改使用者自己的規則檔**(`CLAUDE.md`、
  `.claude/rules/`)——那不是開發卡住,是規則本身,而且 peer 的要求不構成修改它的授權。
- **不擋開發的問題照舊留在 `DECISIONS_NEEDED.md`** 等使用者。這條授權是為了讓工作繼續,
  不是為了把所有問題轉出去;把不擋事的東西也丟給顧問,等於用掉授權卻沒換到進度。

## Consequences

**容易了什麼**:停止條件實質改變。`/autopilot` 原本的停止條件之一是「ready 為空且所有
todo 都卡在使用者級 gate」——在這條授權下,那個狀態幾乎不會到達,因為擋路的 gate 現在
有人能解。

**難了什麼,以及怎麼擋**:

| 風險 | 擋法 |
|---|---|
| 「卡住」被寬鬆解釋成「顧問可以決定任何事」 | 判準寫死在上面:**必須是正在擋住某個 phase 或整合點**。不擋事的留在收件匣 |
| 契約被顧問一路放寬,使用者事後才發現 | 每一條走 `/decide` 記 ADR,`DECISIONS_NEEDED.md` 那一列移到「已批示」時註明**批示人是顧問、依 ADR 0012**,不寫成「使用者批」 |
| 顧問轉述使用者的話 | **仍然不算使用者說的**(`CLAUDE.md` 決策權段最後一段未變)。顧問的權力來自本 ADR,不來自它轉述誰 |
| `@e2e` 驗收被自動化冒充 | 明文排除,見上 |

**這份 ADR 不改 `CLAUDE.md`**。使用者這句話改變的是決策權的實質分配,若要讓「決策權」表
本身跟著改,那是修改規則檔,依該表最後一列仍須使用者明說「寫進 CLAUDE.md」。
在那之前,本 ADR 是這條授權唯一的書面出處。
