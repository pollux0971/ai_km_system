## Scope 說明

本 story 範圍為登入頁「本身」的視覺與互動狀態:表單、驗證、loading、成功、
三種可分類錯誤(帳密錯誤 / 帳號停用 / 服務不可用)、SSO 入口。刻意排除
(留給後續 story):登入成功後導向 return-url(S003)、建立/持久化
app session 與 current-user 載入(S004)。E02(Identity, RBAC & Authorization)
contract 目前為空(`contracts/openapi/core.yaml` 的 `paths: {}`),依
CLAUDE.md「Team A 範圍」與 SOURCE_BASELINE §11 決策 #35(Team A 不等待
Backend),本 story 對 mock AuthClient 開發,並在此記錄。

```
                  message: string }
```

### FIX 紀錄(VERIFY ⇄ FIX,共 1 輪)

1. 第一輪 `pnpm test`:`apps/web` 的 6/12 測試因
   `@testing-library/react` 未在測試間自動 `cleanup()`(專案採逐檔
   `import { ... } from "vitest"` 而非 `test.globals: true`,RTL 的
   auto-cleanup 偵測不到全域 `afterEach`)而在 DOM 中累積前幾個測試的
   render,導致後面的查詢撞到「多個相符元素」。修法:在
   `apps/web/vitest.setup.ts` 顯式 `afterEach(() => cleanup())`。
2. 同一輪 `@ai-km/e2e` 的 2 個新測試因 Playwright 的
   `getByRole(role, { name: string })` 預設是**子字串**比對(非
   Testing Library 的預設完全比對),導致 `name: "登入"` 也命中
   「使用 SSO 登入」按鈕(strict-mode violation)。修法:對登入按鈕的
   locator 加上 `exact: true`。
3. 同一輪 `smoke.spec.ts` 既有(S001)的 `/login` 斷言預期
   「Login (placeholder)」標題——該文字已被本 story 的真實登入表單取代,
   屬於 story 演進的預期結果而非缺陷。修法:更新斷言為新標題「登入」。

修復後從 VERIFY 第一個 gate(typecheck)重新完整跑過,全部通過,詳見上表。

## Assumptions / 計畫外事項

1. **SSO 按鈕行為簡化為「尚未設定」提示**,不嘗試導向任何 URL。理由:
   E02-S12(SSO Abstraction)/E02-S13(OIDC Support)尚未存在,若自行猜測
   一個 SSO 導向 endpoint 會違反 Anti-hallucination Guard(「不得自行
   猜測 endpoint」)。SOURCE_BASELINE 決策 #3 要求支援 SSO,因此按鈕本身
   必須存在(MVP 可簡化行為,不可整個能力缺席)——本實作滿足「按鈕存在
   且有明確互動回饋」,真正 SSO 導向留待 E02 對應 story landed 後補上。
   低風險、可回退、不影響任何跨 Team 介面,故未使用 AskUserQuestion。
2. **成功登入後不導覽/不建立 session**——刻意保留給 E01-S003(redirect)
   與 E01-S004(session bootstrap),避免搶佔其 scope。
3. **真實 audit event(E14)無法產生**,因為 E14 尚無 contract 或
   test double 可呼叫。目前以結構化 log(`packages/logger`)作為
   Thin Slice 替代,已於 AC7 誠實記錄此限制。
4. `tests/e2e` 新增 `@ai-km/auth-client` workspace 依賴,僅用於匯入
   文件化的 mock 觸發常數(避免測試字串與實作漂移),不引入任何執行期
   耦合以外的風險。
