## Scope 說明

本 story 把 S007 留下的「快速入口」靜態佔位文字換成真正的角色感知
entry cards(知識庫/維修助手/ERP 助手)。**重用 S006 的
`nav-items.ts` 表格**(而非另建第二份對應表),讓「哪個角色能看到哪個
入口」在 sidebar 與首頁卡片之間保持單一事實來源——不會出現 sidebar
隱藏維修助手、但首頁卡片仍顯示的不一致情況。

### FIX 紀錄(VERIFY ⇄ FIX,共 1 輪)

1. 第一輪 `pnpm --filter @ai-km/e2e test`:5 個測試失敗,含 3 個**本
   story 新增**的測試與 2 個**S006 既有**測試(`app-shell.spec.ts`
   的「a maintenance_engineer sees...」「a sales_purchasing user
   sees...」)。根因:entry card 與 sidebar nav 項目使用相同標籤文字
   (「維修助手」「ERP 助手」),兩者同時出現在頁面上時,未限定範圍的
   `page.getByRole("link", {name: ...})` 會同時命中 sidebar 連結與
   entry card 連結(Playwright strict mode violation:找到 2 個相符
   元素)。修法:兩個測試檔各自加入以 ARIA landmark 限定範圍的
   helper——`app-shell.spec.ts` 用 `sidebarNav(page)` 限定在
   `<nav aria-label="主導覽">` 內查找;`home-dashboard.spec.ts` 用
   `dashboardMain(page)` 限定在 `<main>` 內查找(sidebar 在
   `AppShell` 中是 `<main>` 的手足元素,不在其內,故此法能正確
   互斥)。**未改動任何生產程式碼**——這是測試 locator 需要跟著新增的
   UI 元素更新範圍,不是元件邏輯的缺陷。

修復後從 VERIFY 第一個 gate(typecheck)重新完整跑過,全部通過。
