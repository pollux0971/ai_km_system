# E01-S012 — 統一 HTTP/domain error presentation

- 狀態:DONE
- Branch:story/E01-S012-unified-error-presentation
- 日期:2026-08-13

## Scope 說明

延續 S011 的模式:在 `packages/ui` 建立共用的錯誤呈現元件
`ErrorMessage` + `errorMessageForCode()`,涵蓋 SOURCE_BASELINE 舊版
(§14 E01-S08)列出的 401/403/404/409/422/429/500(用本專案既有的
語意化代碼慣例命名,非裸 HTTP 數字)以及既有的 `AuthErrorCode` 域碼,
並 retrofit 進 S002/S004/S008 各自獨立寫的錯誤呈現。**「統一」指的是
呈現方式(role=alert + danger 顏色)的一致,不是強制每處文字完全相同**
——LoginForm 的 SERVICE_UNAVAILABLE 訊息刻意保留比通用版本更具體的
「登入服務暫時無法使用」措辭(見下方說明)。**刻意排除**:LoginForm
的欄位層級驗證錯誤(「請輸入帳號」等)——那是不同的 UX 模式(inline
表單驗證,非全域錯誤呈現),不在本 story 範圍。

## 變更檔案

- `packages/ui/src/error-message.tsx` — 新增:`errorMessageForCode()`
  (代碼→通用中文訊息對照表,未知代碼 fail-safe 回傳通用訊息,絕不洩漏
  原始 exception 文字)+ `ErrorMessage` 元件(`role="alert"` +
  `colors.danger` 文字顏色——這是 `design-tokens` 的 `danger` token
  第一次被實際使用)。元件接受 `code`(自動對照)或 `message`/
  `children`(明確覆寫,供呼叫端需要更具體措辭時使用)。
- `packages/ui/src/error-message.test.tsx` — 新增:8 個測試。
- `packages/ui/src/index.tsx` — re-export `./error-message`。
- `apps/web/src/app/(app)/session-gate.tsx` — error 狀態改用
  `<ErrorMessage message="無法載入使用者資訊，請重新整理頁面。" />`
  (保留原本更具行動指引的措辭,只統一呈現方式)。
- `apps/web/src/app/(app)/_components/recent-conversations.tsx` —
  error 狀態改用 `<ErrorMessage message="無法載入最近對話。" />`。
- `apps/web/src/app/(public)/login/login-form.tsx` — 最終錯誤訊息
  render 改用 `<ErrorMessage message={state.message} />`;本地
  `describeError()` 保留不變(新增註解說明為何不換成共用代碼對照表——
  SERVICE_UNAVAILABLE 的登入專屬措辭比通用版本更具體)。欄位驗證錯誤
  維持原樣,未觸碰。

## Assumptions / 計畫外事項

1. **LoginForm 的 `describeError()` 保留本地、未改用共用代碼對照表**:
   SERVICE_UNAVAILABLE 的「登入服務暫時無法使用」比通用版本的
   「服務暫時無法使用」更具體、對使用者更有幫助。這是刻意的設計取捨
   (「統一呈現」≠「強制統一措辭」),已用程式碼註解 + 本檔記錄理由,
   避免被誤解為本 story 沒做完整。
2. **欄位層級驗證錯誤未觸碰**:「請輸入帳號」這類 inline 表單驗證
   訊息是不同的 UX 模式(伴隨特定欄位,非全域錯誤橫幅),不屬於
   「HTTP/domain error presentation」的範圍。
3. **`ERROR_MESSAGES` 目前只包含 7 個 HTTP-flavored 代碼 + 3 個既有
   domain 代碼**:涵蓋 SOURCE_BASELINE 明確列出的清單與目前實際用到
   的代碼;未預先發明目前沒有任何呼叫端會用到的代碼(YAGNI),未來
   story 若遇到新的 error code,可直接擴充這個對照表。
