## 全量 E2E 分析(14 個失敗)

**先確認一個關鍵事實:本 story 自己實際修改的五個頁面,各自的既有
E2E spec 全部通過,零失敗**——`knowledge-list.spec.ts`、
`knowledge-documents.spec.ts`(含 E05-S029 徽章 role 測試)、
`maintenance-home.spec.ts`、`profile.spec.ts`、`login.spec.ts` 皆全綠。
本 story 自己新增的 `pages-m3-axe.spec.ts` 7/7 全綠。

14 個失敗中:

1. **`api-sandbox.spec.ts:143`**(1 個)——斷言 `/v1/health` 回傳
   `status: "ok"`,實際回傳 `"degraded"`。**已獨立確認這是當下真實、
   與本次測試執行無關的環境狀態**:直接 `curl` 共用 apps/api 的
   `/v1/health` 得到同樣的 `"degraded"`(`uptimeMs` 顯示該 process 已跑
   超過 8 小時,不是本次測試啟動的)。與本 story 的改動(純前端
   className/CSS)無任何關聯。
2. **導覽逾時(共 11 個)**:`conversation-detail.spec.ts` ×1、
   `conversation-history-pagination.spec.ts` ×3、`model-selector.spec.ts`
   ×3(皆因同一個「下一頁」按鈕點擊後等不到 URL 變化)、`erp-e2e.spec.ts`
   ×2、`erp-home.spec.ts` ×1、`knowledge-create.spec.ts` ×1、
   `admin-analytics-e2e.spec.ts` ×1。**錯誤訊息的關鍵特徵**:全部是
   `page.waitForURL: Test timeout of 30000ms exceeded`,不是
   `locator.click` 本身逾時或找不到元素——代表點擊動作已經成功執行,
   只是之後的頁面載入/導覽在 30 秒內沒完成。這是效能/延遲特徵,不是
   「點擊目標被我的 CSS 擋住」的特徵(後者會在 `.click()` 那一步本身
   逾時)。失敗分布橫跨對話分頁、ERP、knowledge 建立、admin 回饋佇列
   等彼此無關的頁面與元件,與 `api-sandbox.spec.ts` 觀察到的 API
   degraded 狀態及跑測全程 load average 12~17(非安靜環境)一致,指向
   系統性延遲而非個別頁面的內容缺陷。
   - 其中 `erp-e2e.spec.ts`/`erp-home.spec.ts` 的 3 個失敗發生在本
     story 有改動的 ERP 頁面附近,已特別檢查:失敗的點擊目標
     (`list.getByRole("link", {...}).click()`)是 `erp-query-list.tsx`
     裡我加了 `.m3-list-item-link`(`display: block; color: inherit;
     text-decoration: none;`)的同一個 `<Link>`——這個 class 沒有
     `pointer-events`、沒有定位/z-index 相關規則,純粹是排版與顏色,
     結構上不會擋住點擊;而且錯誤訊息本身已經證明點擊有成功執行
     (逾時發生在 `waitForURL`,不是 `.click()`)。判斷為上述系統性延遲
     的一部分,不是本 story 造成。
3. **`smoke.spec.ts:50`**(1 個)——`getByText('AI KM', {exact:true})`
   同時命中 header 與 Next.js route-announcer 的既知碰撞(W1 的
   E01-S033 處理的同一個問題)。與本 story 無關,本 story 沒有修改
   header/route-announcer 相關的任何檔案。

## Assumptions / 計畫外事項
- **AC3 的 `<th scope>` 措辭假設**:spec 文字「保持既有 `<th scope>`」
  暗示已存在,實際檢查 `erp-query-detail.tsx` 發現原本沒有這個屬性。
  判斷為 AC3 真正要保護的 a11y 語意(表格標頭應有 scope),而非字面
  「維持不變」的意思——已新增 `scope="col"`,純屬性新增,非 DOM 重寫,
  在此誠實記錄理由而非默默略過或請示(風險低、範圍窄、單一屬性)。
- **文件列表非真正 `<table>` 元素**:spec 技術決策提到「knowledge...
  文件列表為 data table」,但實際 DOM(`knowledge-document-list.tsx`)
  是 `<ul>/<li>` 清單,不是 `<table>`。全 repo grep 確認整個 app 只有
  `erp-query-detail.tsx` 一處真正的 `<table>` 元素。判斷:Non-Goals
  明文禁止「重寫任何頁面 DOM」,把這個清單改成 `<table>` 會是 DOM
  重寫,牴觸更高順位的約束;因此文件列表改用 list tiles(`.m3-list`)
  而非表格,AC3 的 data-table 要求由 ERP 的真實 `<table>` 滿足。
- **裸元素規則(button/input/dl/fieldset)刻意不動**:見上方變更檔案
  第 1 點與 SELF-REVIEW 第二項,已用全 repo grep 驗證這是為了不外溢到
  E03-S043(對話頁,明確 Out)而做的刻意選擇,不是遺漏。
