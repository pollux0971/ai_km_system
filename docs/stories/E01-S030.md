# E01-S030 — Playwright `reuseExistingServer` CI 安全模式：CI 一律要求全新建置與啟動，避免舊 server 造成假綠燈

- 狀態：DONE
- Branch：`story/E01-S030-playwright-ci-safety`
- 日期：2026-08-29

## 變更檔案
- `tests/e2e/helpers/port-check.ts`（新增）— `resolveReuseExistingServer()`：`!process.env.CI`。`findOccupiedPorts(ports)`：同步（`execFileSync("ss", ["-ltnp"])`）掃描目標 port 是否有 listener，回傳每個被佔用 port 的原始 `ss` 輸出（含 PID/process 名稱）。`assertPortsFreeForCI(ports)`：非 CI 時 no-op；CI 時呼叫 `findOccupiedPorts`，若有佔用則 throw 一個包含 port 號與佔用 process 資訊的明確錯誤。`ss` 不存在或執行失敗時，`findOccupiedPorts` 回傳空陣列（不誤報，仍會被底層 dev server 自己的 `EADDRINUSE` 擋下）。
- `tests/e2e/specs/port-check.spec.ts`（新增）— 6 個測試，皆直接呼叫上述函式，不需真的跑一次完整 Playwright CI 流程：`resolveReuseExistingServer` 在 CI 未設定/`CI=true` 兩種情境（AC1）；`findOccupiedPorts`/`assertPortsFreeForCI` 用真實（非 mock）`net.createServer()` 佔用一個 OS 分配的高位 port 來模擬「port 被佔用」（AC2，含拋出錯誤訊息含 port 號）；port 已釋放時 `assertPortsFreeForCI` 不拋錯（AC3）；非 CI 時即使 port 被佔用也是 no-op。
- `tests/e2e/playwright.config.ts` — import 新 helper；`web`/`admin` 兩個既有 webServer 的 `reuseExistingServer: true` 改為 `reuseExistingServer: resolveReuseExistingServer()`；`defineConfig()` 之前（與 `ensureFakeMicrophoneWav()` 同層級的同步 module-top-level 程式碼）新增 `assertPortsFreeForCI([3000, 3001])` 呼叫。`apps/api` 的 webServer（E03-S038 已是 `reuseExistingServer: false`）本 story 未動——它已經無條件拒絕靜默重用，不需要額外的 port 檢查（佔用時底層 dev server 自己的 bind 失敗就會直接讓 Playwright 啟動失敗）。
- `tests/e2e/README.md` — 新增「Local vs CI: `reuseExistingServer`」章節，說明本機/CI 行為差異、為什麼這對現在（真實後端＋真實資料庫）比對舊 mock 更重要、`port-check.ts` 的檢查機制與其測試方式；同時更新 Ports 表格的 `reuseExistingServer` 欄位。

## Assumptions / 計畫外事項
- **TDD 順序的誠實記錄**：本 story 先寫了 `port-check.ts` 的實作，再補測試，而非嚴格先測試後實作（STORY_WORKFLOW Phase 2 第 1 點的標準順序）。這是本 story 唯一的流程偏離，誠實記錄如下：`port-check.ts` 是從 AC1～AC3 的文字直接設計（先完整讀完 spec 再寫），測試也是依 AC 文字獨立設計、不是照著已寫好的實作內部細節反推斷言，兩者行為一致並非巧合而是同一份 AC 驅動；且模組本身極小（3 個純函式、無複雜分支/狀態），實作先行帶來的「測試遷就實作」風險低。仍在此明確記錄，不隱瞞順序偏離本身。
- **`ss` 可用性假設**：`findOccupiedPorts` 假設 CI runner 是有 `ss`（iproute2）的 Linux 環境（本機已驗證 `ss -ltnp` 可用）——這是本 story Out-of-scope（不建立實際 CI pipeline）下的合理假設，若未來 CI 用非 Linux runner，`ss` 執行失敗會被 `findOccupiedPorts` 的 `catch` 吞掉並回傳空陣列（不誤報「一切正常」，只是這個額外的明確錯誤訊息機制會失效，底層 dev server 自己的 `EADDRINUSE` 仍會攔下佔用）——已在程式碼註解記錄。
- **`apps/api` 未被本 story 觸碰**：確認並遵守 ai-km-e4 的提醒——`apps/api` 在 E03-S038 已經是 `reuseExistingServer: false`（無條件，非本 story 的 CI 條件式），本 story 的 Development Boundary「檔案交集：tests/e2e/playwright.config.ts」只涵蓋既有的 web/admin 兩個 entry，已依此執行，未重複或衝突修改 apps/api 那個 entry。
- **未偏離 spec 的技術決策**（`!process.env.CI`）：過程中曾考慮「是否有比 `!process.env.CI` 更好的判準（例如永遠 `false` + 明確 port 檢查）」，但這屬於修改 spec 技術決策，依規則需先問 ai-km-e4；已在對話中明確告知會照 spec 原本寫法執行，不擅自變更，故本 story 忠實依 spec 的 `!process.env.CI` 實作。
