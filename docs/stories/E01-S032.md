# E01-S032 — `web:build` 與 e2e webServer 的 `next dev` 競寫 `.next`,完整 `pnpm test` 無法跑完

- 狀態：APPROVED（`/story-review` 獨立審核通過，見下方「獨立審核紀錄」）
- Branch：`story/E01-S032-web-build-serialization`
- 日期：2026-08-29

## 變更檔案
- `tests/e2e/package.json` — `devDependencies` 新增 `@ai-km/admin: "workspace:*"`、`@ai-km/web: "workspace:*"`（spec 建議的最小改動：讓 turbo 的 `^build` 自然把 `web:build`/`admin:build` 排在 `e2e:test` 之前，不需要修改 `turbo.json` 本身的排序規則或 `playwright.config.ts` 的 webServer 指令）。這兩個套件**不是**真的被 `tests/e2e` 的程式碼 import——純粹是宣告給 turbo 的建置圖用，e2e 本身仍透過 HTTP 打 webServer，不透過模組匯入。
- `pnpm-lock.yaml` — `pnpm install` 的必然副作用，只新增 6 行（`@ai-km/e2e` 的 `devDependencies` 條目），無其他變動。

## Contract / Migration 差異
None。

## 問題根因確認（reverted 狀態下的真實重現）
`git stash` 暫時還原 `tests/e2e/package.json`/`pnpm-lock.yaml` 後跑一次真實的 `pnpm test`（持 `.e2e.lock`），**在 4 秒內就重現了與 spec 描述同一類的錯誤**——只是這次命中的是 `admin`，不是 `web`：

```
@ai-km/admin:build: unhandledRejection [Error [PageNotFoundError]: Cannot find module for page: /_document] {
@ai-km/admin:build:   type: 'PageNotFoundError',
@ai-km/admin:build:   code: 'ENOENT'
@ai-km/admin:build: }
```

`admin:build`（`next build`，寫 `apps/admin/.next`）與 e2e webServer 自己的 `next dev -p 3001`（同樣寫 `apps/admin/.next`）並行執行，其中一個先讀到另一個還沒寫完的 manifest，於是找不到 `_document` 這個 Next.js 內部頁面——**與 spec 描述的 web 端症狀（`Cannot find module './315.js'`）是同一種「並行競寫 `.next`」根因，只是這次先命中 admin，不是 web**，佐證這是結構性競爭而非單一套件的巧合。`admin:build` 失敗後 turbo 預設的失敗中止行為（非 `--continue`）連帶把還在跑的 `e2e:test` 中斷（「Test was interrupted」，273 個測試因此沒跑到）。

## 修正驗證：turbo 任務圖排序（AC2 的直接證據）
`pnpm exec turbo run test --dry-run=json --filter=@ai-km/e2e`，逐行核對 `@ai-km/e2e#test` 的 `dependencies` 欄位：

| | `@ai-km/e2e#test` 依賴 |
|---|---|
| **修正前**（`git stash` 還原設定） | `['@ai-km/auth-client#build', '@ai-km/e2e#build', '@ai-km/e2e#check']` —— 沒有 `web`/`admin` |
| **修正後**（本 story） | `['@ai-km/admin#build', '@ai-km/auth-client#build', '@ai-km/e2e#build', '@ai-km/e2e#check', '@ai-km/web#build']` —— `admin#build`/`web#build` 都排進去了 |

這組 before/after 對照直接證明排序確實改變，且與上一節的真實重現（admin:build 的 race）互相呼應：修正前的依賴圖裡沒有 `admin#build`，正是 race 發生的結構性原因。

## Assumptions / 計畫外事項
- **race 這次命中 admin 而非 web**：spec 原本描述的症狀是 web 端（`/citations/[id]`、`/icon.svg`、`/conversations/new` 等頁面），本 story 重現時命中的是 admin 端（`/_document`）——兩者是同一個結構性成因（`build` 與 `dev` 並行寫同一個 `.next`）在不同套件上的展現，不是不同的 bug；本 story 的修正（`@ai-km/web`、`@ai-km/admin` 都宣告為 devDependency）同時涵蓋兩者。
- **`turbo.json` 未修改**：E01-S027 已經把同套件的 `test.dependsOn` 加上 `build`（`["^build", "build", "check"]`），本 story 要補的是**跨套件**依賴，透過 `tests/e2e/package.json` 宣告依賴即可讓既有的 `^build` 規則自然涵蓋，不需要在 `turbo.json` 額外加規則——這與 spec「建議最小改動」的方向一致。
- **12 個既有結構性失敗**：本 story 兩輪驗證中都出現，與本 story 無關，處置屬於 E03-S038 AC1 的既有待裁示範圍（E01-S031 正在修，尚未 merge 回 main）——本 story 不重複處理。
