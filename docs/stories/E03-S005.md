# E03-S005 — Advanced model selector

- 狀態:DONE
- Branch:story/E03-S005-advanced-model-selector

## Scope 說明

SOURCE_BASELINE.md 的 E03 條列式大綱把 S05 標記為「Model Selector /
Advanced mode。」——與 S02(Normal/Advanced 模式切換)的關係是:模型
選擇器**只在 Advanced 模式下顯示**,Normal 模式不提供這個控制項。本
story 新增這個受模式閘控的模型選擇器,並串接 S02 既有的 `ModeSwitch`
讓兩者即時連動(不需重新載入頁面)。

真正的模型註冊表屬於 E12(Model & Prompt Platform,Team B),目前不
存在;`contracts/openapi/core.yaml` 也沒有對應 schema。全 repo 搜尋
GPT/Claude/Gemini/OpenAI/Anthropic/Llama/Mistral 等真實廠商/模型名稱
皆為零筆命中,因此本 story 沒有發明任何真實模型名稱,改用
SOURCE_BASELINE.md 明確列出的三條 baseline 決策(#28 Model 呼叫必須經過
Model Gateway、#29 外部 Cloud LLM 預設關閉、#30 第一優先部署策略為地端)
推導出三個通用選項:兩個預設啟用的地端模型 + 一個**可見但停用**的雲端
模型(不是隱藏——誠實傳達「這個能力存在但尚未開通」,而非假裝它不
存在)。啟用雲端模型是 E11-S13「Model Admin」(Admin Console,尚未
建置)的責任,不在本 story 範圍內。

## 設計決策

1. **`AiModel`/`AiModelOption`/`AI_MODELS`/`DEFAULT_AI_MODEL` 獨立成
   `lib/ai-models.ts`**,不塞進 `conversations.ts`——模型清單本身是
   與「對話」正交的靜態設定資料,未來若 E12 的真實 registry contract
   出現,替換單一模組比在 `conversations.ts` 裡定位程式碼容易。
2. **`ConversationSummary.model` 為必填,不可為 `null`**——與可以
   合法「什麼都不選」的 `knowledgeScopes` 不同,對話要產生任何回應都
   一定需要某個模型,即使目前是 Normal 模式、選擇器沒有顯示。
3. **`setConversationModel` 在伺服器端(mock 層)重新驗證選項是否
   `disabled`**,不能只信任 UI 的 `<option disabled>`——這正是把
   Deny-Wins 套用在「使用者明確選擇」而非「自動 fallback」上:即使有
   人繞過前端直接呼叫這個函式,停用中的雲端模型依然會被
   `VALIDATION_ERROR` 擋下,符合 AI/RAG Boundary「Model/provider
   fallback 不得把資料送往未允許的 external provider」的同一保證。
4. **單選維持 `<select>`,不是像知識來源那樣改成核取方塊群組**——
   一次對話永遠只用一個模型產生回應,epic 裡沒有「多模型」故事的
   S03→S04 那種單選→多選演進路徑。
5. **`ModeSwitch` 新增 `onModeChange?` callback prop**,而非把整個
   mode 狀態上提——`ConversationDetail` 只需要知道「目前是不是
   advanced」來決定是否顯示 `ModelSelector`,不需要接管 `ModeSwitch`
   內部的 `pending`/`error` 狀態,維持元件職責單一。
6. **`ConversationDetail` 用獨立的 `currentMode` state(初始化自
   `getConversation` 的結果,之後由 `onModeChange` 更新)**,而不是
   直接讀 `state.conversation.mode`——因為 `state.conversation` 是
   載入當下的快照,不會因為之後切換模式而自動更新;若不獨立追蹤,
   使用者切到 Advanced 模式後 `ModelSelector` 不會出現。

### Security / Authorization Acceptance

- **Deny Wins 的具體套用**:`setConversationModel` 在 mock 層重新驗證
  `disabled` 選項並拒絕,不單靠前端 `<option disabled>`——延續
  `docs/stories/E03-S005.md` 設計決策 3 的論證,即使前端被繞過也不會
  真正切換到停用中的雲端模型。
- 其餘 authorization 相關 AC(revoked permission、unauthorized source
  不得進入 LLM context)延續 E03-S001~S004 已確立的既有論證:目前無
  下游 LLM/RAG 呼叫(E04/E12 皆不存在),此 story 不引入新的受保護
  資源或角色判斷。
- 所有外部輸入(使用者選擇的 model id)皆對照 `AI_MODELS` 白名單驗證,
  非僅信任 TypeScript 型別。

（`"standard"`/`"advanced-local"`/`"cloud"`),UI 顯示文字

## Assumptions / 計畫外事項

1. **雲端模型選項「可見但停用」而非「隱藏」**:SOURCE_BASELINE 沒有
   明講 UI 呈現方式,但決策 #29「外部 Cloud LLM 預設關閉」用詞是
   「預設關閉」而非「不存在」,因此選擇誠實呈現能力存在但未開通,
   而非假裝它不存在。
2. **模型選項目前沒有角色差異化規則**:`AI_MODELS` 沒有
   `KnowledgeScope` 那樣的 `roles` 欄位——SOURCE_BASELINE 未定義任何
   模型的角色限制,依「不發明」原則不新增這個維度。
3. **`ModeSwitch` 的 `onModeChange` 只在成功時呼叫**:失敗或維持原值
   時不觸發,避免 `ConversationDetail` 收到「假的」模式變更事件。
