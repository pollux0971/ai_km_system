## 變更檔案
- `packages/api-client/package.json` — 新增 `openapi-fetch` 依賴、`vitest`/`jsdom` devDependency、`test`/`check` script,`generate` 改指向 `scripts/generate.mjs`。
- `packages/api-client/scripts/generate.mjs` — 對 `contracts/openapi/{core,auth,conversations,transcriptions}.yaml` 逐檔產生 `src/generated/<name>.d.ts`;缺檔跳過並列警告,exit 0。真正的 codegen 呼叫 `openapi-typescript`(以 `file://` URL 傳入,因為 `auth.yaml`/`transcriptions.yaml` 等會 `$ref` 到 `core.yaml` 的共用 schema,需要跨檔解析)。
- `packages/api-client/scripts/check.mjs` — `generate` 後 `git add -N`(intent-to-add,讓從未 commit 過的新產生檔也會被 diff 偵測到)再 `git diff --exit-code -- src/generated`;drift 時回傳差異內容。
- `packages/api-client/src/client.ts` — `createApiClient({baseUrl, fetch?, clientId?})`:回傳按 spec 分組的 `openapi-fetch` typed client(`core`/`auth`/`conversations`/`transcriptions`);`credentials:"include"`;middleware 注入 `x-correlation-id`(呼叫端已設定時不覆寫)與 `x-client-id`(`sessionStorage["ai-km:client-id"]` 持久化,無 `sessionStorage` 時退回每個 client 實例一個 uuid,供 BFF 等非瀏覽器情境呼叫端可用 `clientId` 覆寫)。
- `packages/api-client/src/result.ts` — `toResult(pending)`:接收「尚未 await 的 openapi-fetch 呼叫」,統一在這裡 try/catch 掉網路錯誤/非 JSON body(→`SERVICE_UNAVAILABLE`),401 一律正規化為 `UNAUTHENTICATED`(不論 body 內容),其餘非 2xx 依 Error 封套的 `code` 回傳,型別沿用既有 `@ai-km/types` 的 `Result`/`ApiError`。
- `packages/api-client/src/index.ts` — 重寫,匯出 `createApiClient`/`toResult`/各 spec 的 `paths`/`components` 型別;移除舊的 `ApiClientPlaceholder`(repo 內確認無任何 consumer 引用它)。
- `packages/api-client/src/generated/{core,auth,conversations,transcriptions}.d.ts` — 真實 `generate` 輸出,committed。
- `packages/api-client/src/generated/.gitkeep` — 刪除(目錄已非空)。

## Assumptions / 計畫外事項
- `openapi-typescript` 的 programmatic API 對 `file://` URL 輸入會用 `@redocly/openapi-core` 的 resolver 做跨檔 `$ref` 解析;在 vitest 的 `jsdom` environment 下会因為 jsdom 覆寫 `fetch`/URL 全域而壞掉(`Unsupported schema format`)。這不是 spec 規定的行為,是本 story 開發中發現的第三方套件在特定測試 runtime 下的相容性問題;處理方式是把 vitest 預設環境改成 `node`,只在需要 `sessionStorage` 的 `client.test.ts` 用 per-file `@vitest-environment jsdom` 覆寫。記錄於此,若未來要幫這個 package 加瀏覽器限定的測試,需注意這個環境切換慣例。
- `createApiClient` 在沒有 `sessionStorage` 時(例如 BFF route handler 在 Node 執行環境呼叫)退回「每個 client 實例一個 uuid,不持久化」,而非拋錯。spec 沒有明講這個情境的行為,但 CLAUDE.md 鐵律 3(BFF 也必須透過 `@ai-km/api-client`)隱含這個 package 會在非瀏覽器環境被呼叫,若不處理會直接噴錯導致 BFF adapter 全部無法用。呼叫端(BFF)應該傳入明確的 `clientId`;這點已寫進 README。標記為 ASSUMPTION,E03-S035 起的 adapter 若有不同需求可推翻。
- 全 repo `pnpm turbo run typecheck lint test` 一次平行跑會出現 `@ai-km/web`/`@ai-km/admin` 的暫時性失敗(逐一單獨重跑全綠),判斷為本機多條 lane 同時跑造成的資源競爭,不是本 story 造成的迴歸,細節見上方 Gate 紀錄。
- **補充驗證(2026-08-28,來源:W7 持鎖乾淨基準,ai-km-e4 回填)**:對應 main `d1e8286`(含本 story 的 `turbo.json` 變更),持鎖、無 port 互搶、機器負載正常的條件下重跑全 repo:`turbo run typecheck --force` 23/23、`turbo run lint --force` 23/23、unit 全 package 合計 2101/2101 全綠(含本 story 的 api-client 21/21)、E2E 261/264(6.9 分鐘)。3 個失敗全部是 `page.goto`/`waitForURL` 的 30000ms 逾時(`admin-e2e.spec.ts`、`admin-analytics-e2e.spec.ts`、`maintenance-e2e.spec.ts`),沒有斷言內容不符/資料錯誤/型別錯誤;若 `turbo.json` 的 task 圖真的被改壞,預期會看到 build/import/型別錯誤或功能性斷言失敗,而不是清一色的導航逾時 —— 加上 typecheck/lint/2101 個 unit test(對 `dependsOn` 正確性極敏感)全綠,佐證這 3 個逾時是既有資源競爭型 flaky,與本 story 變更無關。此基準線同步記錄於 main 的 `ROADMAP_TEMP.md` 第 5-ter 節。
