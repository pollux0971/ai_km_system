## Assumptions / 計畫外事項
1. **元件放置路徑**:spec 只寫檔名(`voice-visualizer.tsx/.css`)未給完整
   路徑。story 的「禁止修改」清單明文包含 `packages/*`(`packages/ui` 這種
   共用元件庫因此不可用),故選擇 apps/web 內新建
   `apps/web/src/components/voice/`(與既有 `apps/web/src/lib/voice/`
   語意區分:lib = 無 UI 的錄音邏輯,components = Experience/Design Asset
   層的可視元件,符合 spec Metadata 的 Layer 標註)。
2. **`docs/design/voice-visualizer/*.png` 資產子目錄**:「允許修改」清單
   只寫 `docs/design/voice-visualizer.md(新增)`,未明文列出圖片資產路徑。
   但 AC7 明文要求該文件「附四態＋reduced-motion 五張截圖」,markdown
   需要實際圖片檔案才能真的嵌入(不能只是文字宣稱),因此視為該新增文件的
   必要資產延伸,建立同名子目錄存放 5 張 PNG。範圍上只新增這一個子目錄,
   未觸碰其他任何路徑。
3. **`--md-sys-color-on-error` 無對應現行 fallback token**:spec 只明講
   `--md-sys-color-primary-container` fallback `--primary-soft`,其餘顏色
   的 fallback 由實作者決定。`globals.css` 現有的 `--on-primary`(白/深藍,
   隨明暗模式切換)在深色模式下是深色,直接拿來當 error 底色上的圖示色會
   對比不足,因此改用硬編 `#ffffff`(輔以 M3 token 優先的 fallback chain,
   `--md-sys-color-on-error` 一旦存在會優先採用),兩種模式下皆與紅色底
   有足夠對比。E01-S021 落地後可視覺複驗是否需要調整。
4. **Reduced-motion 下 error 的 shake 一併停用**:spec 只明講 ripple/bar
   與旋轉弧改靜態,未提及 error 的一次性 shake。反射性動態(vestibular
   trigger)包含短促位移動畫,依 `prefers-reduced-motion` 的一般精神(抑制
   非必要動態)一併停用,而非鑽 spec 沒明講的空子照樣播放。CSS 內以
   `@media (prefers-reduced-motion: reduce) { .vv-error--shake { animation:
   none; } }` 實作,元件本身也不加 `vv-error--shake` class(見
   `ErrorGlyph`)。
5. **AC1 的「snapshot 只用於結構」**:未使用 vitest 的
   `toMatchSnapshot()`(repo 目前 1500+ 測試中沒有任何既有 `.snap` 檔案,
   引入第一個會造成測試風格不一致,且 snapshot 檔案本身不易在 code review
   時看出斷言了什麼)。改用明確的結構性斷言(子元素數量、`data-testid`、
   `data-state`),不斷言任何 inline style/class 的視覺細節,精神上等同
   spec 要求的「只驗結構、不驗樣式」。
6. **Level 指數平滑的實作方式**:spec 只說「高度=level 經指數平滑」未定義
   平滑係數或觸發時機。實作用 `useEffect` 在 `[state, clampedLevel]`
   變動時做一步 EMA(`prev + (target-prev)*0.35`),而非 `useRef` 純
   render-time 突變(避免 React 19 StrictMode 下 impure render 的疑慮)或
   `requestAnimationFrame` 迴圈(需要额外的 rAF mock 才可測,且 AC 並未
   要求逐 frame 的動畫本身可測,只要求「level 改變時樣式改變」)。平滑
   係數 0.35 為合理預設值,非 spec 明定,E03-S041 接上真實麥克風後如有
   體感問題可調整,不影響本元件對外 API。
