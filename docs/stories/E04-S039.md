## 測試修正記錄

依 TDD 先寫全部 68 個測試,確認為紅(6 個 test file 全部 `Cannot find module`,
exit 1),才開始實作。**沒有刪除或放寬任何測試**。兩筆測試檔異動,兩者都是
「新增/基礎設施」而非放寬,逐筆記錄:

1. **`src/server.test.ts` 的 `build()` helper 加上預設 `AI_KM_LOG_LEVEL=silent`**
   —— 純測試基礎設施(68 個測試每個都印兩行 NDJSON,把真正的輸出淹掉),
   沒有改動任何斷言。**關鍵**:只在**未傳入 log sink 時**套用;有傳 sink 的
   測試(唯一斷言 log 內容的那一個)維持 `info`。若無差別套用,
   「log 裡沒有 secret」會因為根本沒有 log 而**假性通過**——這正是要避免的。
2. **同檔「logging hygiene」測試新增兩條非空斷言**
   (`sink.lines.length > 0`、`sink.raw` 含請求 URL)—— 這是**新增**斷言,
   目的正是消除上一點所述的假性通過風險:先證明 log 真的有在寫,「不含
   secret」才有意義。

以上皆非 Phase 4 第 5 點的「測試技術性錯誤」例外——沒有任何既有斷言被修改
或放寬。

## 技術決策(規格未指定、由本 story 決定,供後續 story 沿用)

1. **`module: NodeNext` + 相對 import 帶 `.js`** —— `apps/api` 必須以
   `node dist/main.js` 真正執行。沿用 repo 其他 package 的
   `module: ESNext` + `moduleResolution: Bundler` 會產出 Node 無法解析的
   無副檔名 import(那些 package 都是 `--noEmit`,不需執行,所以沒踩到)。
   已用編譯產物實跑驗證。
2. **request 驗證改用自訂 validator compiler** —— Fastify 內建 Ajv 預設
   `removeAdditional: true`,會**靜默丟棄**契約未宣告的欄位。對 contract-first
   的 API 這是雙重錯誤:client 以為成功但請求被削掉一半,而打錯的欄位名變成
   隱形而不是 400。因此 **body 嚴格且不做型別轉換**(契約寫 `integer`,`"3"`
   就是 client 的 bug),**query/params/headers 保留轉換**(線路上本來就都是
   字串)。已於 README「Request validation is strict」小節說明。
3. **`__test__` 路由的雙重閘門** —— 綁「非 production」**且**「已載入
   `src/testing/fixtures` 的 sample spec」。該 fixture 只有測試會傳入,所以
   這些路由連 dev server 上都不存在(實跑驗證:dev server 打 → 404)。

## Assumptions / 計畫外事項

1. **`pnpm-lock.yaml` 被修改(計畫外,但不可避免)** —— 新增一個有依賴的
   workspace package 必然改動 lockfile;不提交會讓 repo 與已安裝的樹不一致。
   已逐行檢查影響範圍:**沒有任何既有套件版本改變**
   (`@babel/core@7.29.7`、`next@15.5.23`、`@vitejs/plugin-react@4.7.0` 皆
   原封不動),變的只是 pnpm 的 peer 解析 key 多了 `(supports-color@10.2.2)`
   —— `supports-color` 是 `apps/api` 依賴鏈帶進來的 optional peer。為求保險,
   在此狀態下跑了**完整 264 個 E2E,全數通過**,確認共用解析改變沒有造成回歸。
2. **`AI_KM_API_HOST` 未做格式驗證** —— 規格只列出它要被讀取。主機名/IP 的
   合法性交由 Node 的 `listen()` 判斷(它會以明確錯誤退出),沒有自己再寫一套
   可能與 Node 不一致的驗證。
3. **`x-client-id`(E04-S038 的 `originClientId` 來源)尚未在此實作** ——
   它屬於會發事件的 domain plugin(E04-S041～S044),骨架不需要知道它。
4. **`migrate` script 是會以非零退出的 placeholder** —— 規格明寫本 story 只留
   placeholder。它**不是**靜默的空操作:誤用會得到明確訊息與非零 exit code,
   而不是假裝遷移成功。
5. **`buildServer` 的 `contractsDir` 是選項而非新 env 變數** —— 規格把
   `config.ts` 該讀的 env 列得很明確,不擅自增加;測試改以參數注入 fixture 目錄。
   正式路徑用 `resolveContractsDir()` 逐層往上找 `contracts/openapi`,在 `src/`
   (tsx)與 `dist/`(node)下都成立。
