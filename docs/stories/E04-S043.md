真實整合 smoke(`buildServer()`,非本 package harness):
```
PUT .../feedback {verdict:"NG"}                       -> 200, feedback:"NG"
PUT .../feedback/reason {reason:"INCOMPLETE"}         -> 200, feedbackReason:"INCOMPLETE"
```

四個維度的欄位在最後一次回應中同時存在、互不覆蓋(AC7)。

## Assumptions / 計畫外事項
1. **`getMessageByOwner` 新增匯出**:為避免 `message-feedback.repository.ts` 複製一份 `toMessage`/`RawMessageRow` 映射邏輯(原本會是近 40 行重複),在 `messages.repository.ts` 新增一個小型、owner+id 純查詢的匯出函式供其重用。此函式明確不做 403/404 判斷(那由呼叫端在 `getMessage` + `lookupConversation` 已完成),僅用於寫入後的 re-select。
2. **comment 原文不進 log 的驗證方式**:本 story 未新增專門斷言「log 不含 comment 原文」的測試,因為路由層從未把 `comment` 傳給任何 log 呼叫(唯一經過 log 的路徑是既有 `apps/api` 錯誤處理器,只記錄固定的錯誤代碼與訊息,不含請求 body)——這是沿用 E04-S039/E04-S041 既有、已測過的 log 政策,而非本 story 新增的行為,故未重複測試。
