## Scope 說明

E05 的第十五個 story。與 S001-S014 相同情況:SOURCE_BASELINE.md 對 E05
只有一份扁平標題清單,本 story 在 epic 檔中只有標題,無進一步內文。已讀
過 epic 檔本 story 自己的章節(line 2952-3161,下一節「Folder sync
setup UI」從 line 3162 開始),並用 `diff` 直接逐字比對本 story 章節
與 S014 章節的內文(排除 H1 標題與「User / System Value」段落唯一的
story 名稱代換),確認兩者逐字相同,是通用 MVP 樣板文字,無本 story
專屬內容。

**與 S011-S014 的關鍵差異:第一次有真實內容可以誠實儲存**——S011-S013
(檔案)刻意不讀取/儲存真實檔案位元組(Frontend/BFF 不得直連 Object
Storage);S014(URL)刻意不擷取任何真實內容(沒有真正的擷取管線)。
本 story 完全相反:使用者**直接輸入的文字本身就是內容**,沒有檔案
要讀、沒有網址要擷取,文字在瀏覽器裡就是真實、完整存在的資料。這讓
本 story 面臨與 S011-S014 相反的問題:不是「該不該假裝有資料」,而是
「明明有誠實可得的真實資料,沒有理由不儲存」。

## 設計決策

1. **`KnowledgeBaseDocument` 新增選填的 `content` 欄位,真的儲存輸入
   的文字**——與 S011-S013(不存真實檔案內容)、S014(不存在任何
   內容)不同,本 story 的文字內容是誠實可得的,不儲存反而會讓
   「文字知識輸入」這個功能名不符實。純新增選填欄位,既有的檔案/
   URL 來源文件完全不受影響(它們的 `content` 就是不存在,不是
   刻意留空)。
2. **`sizeBytes` 是真實計算出來的位元組數(`new Blob([content]).size`),
   不像 S014 的 URL 匯入省略這個欄位**——刻意記錄下這個與 S014
   相反的選擇:URL 匯入省略 `sizeBytes` 是因為根本沒有位元組可回報
   (沒有任何真實擷取發生);本 story 的文字內容確實存在、確實可以
   準確計算真實 UTF-8 位元組長度,計算並記錄它是誠實的,不是捏造
   ——同一套「不假裝擁有不存在的資料」原則,套用到不同情境會得出
   不同(但邏輯一致)的結論。用 `Blob` 而非單純字元數,是因為
   Blob 的 size 計算會正確反映 UTF-8 編碼後的真實位元組數(中文字元
   通常佔 3 位元組,不是 1),與檔案上傳路徑記錄的 `file.size`
   語意一致(都是真正的位元組數,不是字元數)。
3. **標題與內容是兩個獨立欄位,不是單一輸入**——與
   `createKnowledgeBase` 的 `name`/`description` 分離同一種考量,
   也與 `addKnowledgeBaseDocumentFromUrl` 的單一 `url` 欄位不同
   ——網址本身沒有獨立於網址之外的「標題」概念,但使用者輸入的知識
   天生就有「給這段內容一個名稱」與「內容本身」兩個不同東西。
4. **內容為空時明確拒絕(`VALIDATION_ERROR`),不像 S008 的
   `boundPrompt` 允許空白**——`boundPrompt` 的空字串是有意義的合法
   狀態(「不使用自訂提示詞,回退預設」);本 story 的內容若允許
   空白,產生的文件毫無意義——這個能力存在的唯一目的就是新增真實
   內容,因此空白提交比照空白檔名/格式錯誤網址,一律拒絕。
5. **`KnowledgeDocumentTextInput` 是第三個獨立元件,不是塞進既有
   兩者之一**——延續 `KnowledgeDocumentUrlImport` 自己 doc comment
   已經建立的「每種根本不同的互動形狀各自獨立元件」原則:這是
   標題欄位+多行文字框+明確送出,既不是檔案選取器,也不是單一
   網址欄位。渲染在同一個 `/knowledge/[id]/documents` 頁面,共用
   同一個 `refetchDocuments` callback(以 `onAdded` 傳入)。
6. **儲存的 `content` 本身目前不在任何地方顯示**——本 story 的標題
   是「輸入」,不是「檢視」;文件列表沿用既有的 name/size/time
   摘要格式,不新增顯示內容全文的能力(與 S008 的 `boundPrompt`
   摘要只顯示「已設定」、不顯示提示詞全文,是同一種「輸入能力≠
   檢視能力,檢視是自己的、尚未到來的 story」範圍紀律)。
7. **Telemetry 排除標題與內容,但包含 `sizeBytes`**——標題與內容
   都是使用者自由輸入的文字,延續 S008(提示詞)/S011(檔名)/
   S014(網址)一致的「不記錄自由格式內容」克制;`sizeBytes` 是
   安全的數字型資料,延續既有先例記錄。
