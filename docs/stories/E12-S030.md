### 開發機——`verify-asr`:管線已用**真實 GPU 推論**驗證,但還不是 AC6 要的那個 PASS

真的啟動了 `whisper-server`(真實模型、真實 GPU),真的用 `verify-asr`
的程式碼對它送出一個**合成**(非真人語音,`ffmpeg` 產生的 5 秒 440Hz
正弦波)音檔,證明整條管線(multipart 上傳、真實 HTTP 往返、真實 GPU
推論、JSON 解析、OpenCC 正規化、關鍵詞比對、耗時量測、exit code)全部
正確運作,不是只測過 fake sidecar:

```
$ tail -f whisper-server.log(啟動片段)
ggml_cuda_init: found 1 CUDA devices (Total VRAM: 3716 MiB):
  Device 0: NVIDIA GeForce GTX 1650, compute capability 7.5, VMM: yes, VRAM: 3716 MiB
whisper_model_load:        CUDA0 total size =   573.45 MB
(...whisper-server 監聽 127.0.0.1:8178...)

$ node 一次性腳本呼叫 runVerifyAsr({fixturePath: "<合成正弦波.wav>"})
{
  "kind": "fail_quality",
  "text": "字幕志願者 李宗盛\n",
  "hitRate": 0,
  "isTraditional": true,
  "elapsedMs": 3576
}
```

`"字幕志願者 李宗盛"` 是 whisper 對無語音輸入的典型幻覺輸出(業界廣泛
回報過的現象,E12-S031 的 `normalize.ts` 幻覺黑名單機制正是為了過濾
這類東西而存在)——這正確地被 `verify-asr` 判定為 `fail_quality`
(關鍵詞命中率 0%),`exit code` 非 0,**沒有 crash、沒有誤判成功**。這
證明了程式邏輯正確,但**合成正弦波不是 AC6/spec 要求的「真人中英夾雜
語音」**,所以這一步刻意不算作 AC2 的 PASS 證據,誠實記錄為「管線驗證
通過,語音內容驗證未通過(因為輸入本來就不是語音)」。

測試完成後已確認:`whisper-server` process 已終止、port 8178 已釋放、
`git status` 乾淨(複製進來的 `.bin` 檔案確認被 `.gitignore` 排除,
`git add -n` 乾跑確認不會被加入 staging)。

## 還缺什麼(給使用者的下一步,已寫進 `fixtures/README.md`)

`verify-asr` 需要一個**真人**錄的中英夾雜音檔才能完成 AC2 的真正 PASS
(命中率 ≥80% 且為繁體)。這是本 story 唯一沒辦法由 AI 自己解除的阻塞
(比照 E12-S031/E03-S041 卡住的同一個原因)。

**使用者要做的事(已在 `tools/asr-readiness/fixtures/README.md` 寫清楚)**:
1. 用自然語速唸:「請幫我確認一下這個 API 的 error code,然後把
   deadline 更新到系統裡,謝謝。」(8–15 秒,繁體中文夾雜
   `API`/`error code`/`deadline` 這幾個英文技術詞彙)。
2. 錄成 16kHz mono PCM16 WAV(`README.md` 附兩種指令:`ffmpeg -f alsa
   -i default -ac 1 -ar 16000 -sample_fmt s16 sample-zh-en.wav` 或
   `arecord -f S16_LE -c 1 -r 16000 -d 12 sample-zh-en.wav`)。
3. 存成 `tools/asr-readiness/fixtures/sample-zh-en.wav`(不進 git,已由
   `.gitignore` 排除)。
4. 啟動 sidecar:`tools/asr-readiness/scripts/asr-server.sh
   ggml-large-v3-turbo-q5_0.bin`(本機用 q5_0;4070 到位後用
   `ggml-large-v3-turbo.bin`)。
5. 跑 `pnpm --filter @ai-km/tool-asr-readiness verify-asr`,把輸出貼回
   這份 EVIDENCE(或告知總指揮,由他補上)。

如果唸的內容跟預設關鍵詞不同,直接編輯
`tools/asr-readiness/fixtures/expected.json`(純文字關鍵詞清單,不是
音檔,可以進 git)即可,不需要改任何程式碼。

補完這一步後,**E12-S030、E12-S031(AC8)、E03-S041(L3)三個 story 的
證據鏈會一起解開**——這也是這次改派的原因。

## 測試修正記錄(若有)
測試撰寫後未回頭修改斷言配合實作。紅→綠除錯過程中修正的是**實作本身
的真 bug**,不是放寬測試:
- `findWhisperServerBinary` 的 Windows PATH 測試
  ("looks for the .exe suffix on Windows")一開始失敗,原因是實作用
  Node 的 OS-native `path.delimiter`/`path.join`(在 Linux 上執行時永遠
  是 POSIX 語意),即使有注入 `platform:"win32"` 參數也不會改變
  `path` 模組本身的行為,導致在非 Windows 機器上永遠無法正確解析
  Windows 風格的 `PATH` 字串。這是**實作的真 bug**(在 Linux CI/開發機
  上跑這個工具驗證 Windows 邏輯的測試會一直錯,不是測試寫錯),已改用
  `path.win32`/`path.posix` 依目標平台明確選擇對應的路徑模組,修正後
  重跑全部 46 個(當時)測試皆綠。
