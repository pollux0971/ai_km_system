# E01-S033 — `smoke.spec.ts` 的 `getByText('AI KM')` 撞上 Next.js route-announcer

## Metadata
- Epic: E01 Application Shell & User Workspace
- Owner: Team A(W2)
- MVP: Required(它是 golden path smoke,誤報成本最高)
- Story size target: 0.25 developer-day

## 問題陳述
`smoke.spec.ts:50` 的 golden path 測試用
`getByText('AI KM', { exact: true })` 取得 header 品牌字樣,但 Next.js 會在
每次導覽時注入 `<div id="__next-route-announcer__">`,其內容在導覽瞬間同樣是
頁面標題「AI KM」→ **strict-mode violation(resolve 到 2 個元素)**。

**這不是 flaky,是未 scope 的 selector。** 觸發窗口窄(只在導覽的短暫瞬間),
所以只在部分輪次命中——2026-08-29 本 session 已**兩次獨立重現逐字相同的錯誤**
(E01-S031 rebase 前那輪、統一 E2E 驗證那輪)。

**repo 內已有此碰撞的既知處理方式**,本支是漏網:
```
tests/e2e/specs/error-boundary.spec.ts:17    「Next.js injects its own role="alert" route announcer…」
tests/e2e/specs/knowledge-documents.spec.ts:371 「Next.js's own hidden route-announcer div…」
tests/e2e/specs/knowledge-create.spec.ts        同一碰撞
```

## Scope In
- 把該 selector **scope 到 header/main 等明確容器**(比照上列三支既有先例的
  處理方式,不要發明新模式)。
- 掃描 `tests/e2e/specs/**` 是否還有其他未 scope、可能撞上 route-announcer 的
  `getByText` / `getByRole("alert")`,一併列出(修或說明為何不受影響)。

## Scope Out
- 不改任何 production 程式碼(route-announcer 是 Next.js 行為,不是缺陷)。
- 不改該測試的**意圖**——它仍必須驗證 header 顯示品牌字樣。
- 不加 retries / skip。

## Functional Acceptance Criteria
1. `smoke.spec.ts` 的 golden path 通過,且**仍然驗證 header 的品牌字樣**
   (不得改成驗證別的東西或直接刪掉該斷言)。
2. **反向驗證**:證明修法真的對應根因——例如以 `page.evaluate` 在斷言前
   注入一個含相同文字的 route-announcer,確認**修正前會 strict-mode 失敗、
   修正後仍通過**。單靠「跑幾輪沒中」不算達成(觸發窗口本來就窄)。
3. 掃描結果:其餘 spec 的同類風險已列出並處理或說明。
4. 全量 E2E 跑一次,記錄跑前跑後 `uptime`。
