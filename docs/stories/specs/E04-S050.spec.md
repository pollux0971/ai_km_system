# E04-S050 — domain plugin 依載入的 contract spec 條件註冊,讓 route 能真正使用 `app.contracts.getSchema()`

## Metadata
- Epic: E04 RAG & Conversation Intelligence(使用者增補追蹤範圍)
- Owner: Team A
- MVP: Required(解除後續所有 apps/api route story 的逐字轉寫負擔)
- Story size target: 0.25–0.5 developer-day
- Story 來源: E04-S042 EVIDENCE 記錄的發現;總指揮依使用者 2026-08-28
  對 E04-S049 的同類裁示授權新增

## 問題陳述
`apps/api/src/server.ts` **無條件註冊** `conversationPlugin`(第 153 行)。
但 `server.test.ts`、`db/migrate.test.ts`、`contracts.test.ts` 等 bootstrap
測試刻意用只含 `sample.yaml` 的 fixture 契約目錄
(`apps/api/src/testing/fixtures/`)建 server,以隔離測試 bootstrap 行為。

因此一旦 domain route 在註冊階段呼叫 `getSchema("conversations", …)`,
fixture 裡沒有該 spec 就會拋錯。W3 實測:把 `messages.ts` 改用真的
`getSchema()` 後,`apps/api` 91 個測試中有 **28 個** 直接失敗。

**這與 E04-S049 修好的順序問題完全獨立**,是第二個成因。後果相同:
E04-S043、E04-S044、E04-S047、E04-S048、E02-S034、E12-S031 等所有新增
apps/api route 的 story 都必須繼續逐字轉寫 JSON Schema,而轉寫的 schema
與 `contracts/openapi/` 之間**沒有機器檢查**,是 contract drift 的溫床。

## Scope In
- 讓 domain plugin 的註冊**以「該 domain 的 spec 是否已載入」為條件**。
  repo 內已有此模式的先例:`server.ts` 第 175 行的
  `contracts.specNames().includes("sample")` 決定是否註冊 `__test__` routes。
  建議比照,但實作方式由開發者判斷(亦可用 `BuildServerOptions` 明確開關,
  需說明取捨)。
- 新增迴歸測試:
  - 以 fixture 契約目錄(只含 `sample`)建 server → **不註冊** domain plugin,
    且 server 正常啟動;
  - 以真實契約目錄建 server → domain route 存在且可用
    `getSchema()` 綁定 schema 而不拋錯。
- 將 **`services/conversation` 內既有的逐字轉寫 JSON Schema 至少改回一處**
  真正的 `getSchema()` 呼叫,以證明本 story 真的解除了限制
  (不是只改 server.ts 卻沒人受益)。改哪一處由開發者選,EVIDENCE 需說明。

## Scope Out
- **不需**把 E04-S041/S042 所有逐字轉寫全部改回——只要證明機制可用即可,
  其餘由後續 story 自然採用。
- 不新增/修改任何 contract yaml。
- 不改 `apps/web`、`apps/admin`、`db/*`、`packages/*`。

## 依賴關係

  (問題發現來源,已 approved)。
- 下游 Story:E04-S044、E04-S047、E04-S048、E02-S034、E12-S031 —
  皆因此不必再逐字轉寫。

## Functional Acceptance Criteria
1. Given 只含 `sample` spec 的 fixture 契約目錄,When `buildServer()`,
   Then domain plugin 不被註冊、server 正常啟動、既有 bootstrap 測試全綠。
2. Given 真實契約目錄,When `buildServer()`,Then domain route 正常註冊,
   且其 schema 由 `app.contracts.getSchema()` 取得時不拋錯。
3. `apps/api` 既有 91 個測試**零修改**且全綠。
4. `services/conversation` 既有 147 個測試**零修改**且全綠。
5. 至少一處逐字轉寫已改回 `getSchema()`,且該 route 的既有測試零修改全綠。

  回 404(Fastify 預設),不得回 200 或洩漏任何資料。
