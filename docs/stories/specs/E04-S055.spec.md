# E04-S055 — `require-session.test.ts` 寫死日期,跨日後必然全紅(時間炸彈)

## Metadata
- Epic: E04(使用者增補追蹤範圍)
- Owner: Team A(W2,`services/identity` 的 domain owner)
- MVP: **Required — main 目前為紅,turbo 因此中止整條 pipeline,擋住所有 lane**
- Story size target: 0.25 developer-day

## 問題陳述(總指揮已獨立重現)
```
services/identity/src/require-session.ts:39
  export const SESSION_IDLE_LIMIT_MS = 12 * 60 * 60 * 1000;   // 12 小時

services/identity/src/require-session.test.ts:16
  const NOW = "2026-08-28T05:00:00.000Z";                      // 寫死
```
`seedSession()` 以 `NOW` 當 `last_seen_at` 寫入 DB,而 `buildRealRequireSession`
用**真實 wall-clock** 計算 `idleMs = nowMs - Date.parse(row.last_seen_at)`。
測試**沒有使用假時鐘**(`grep useFakeTimers` 零命中)。

因此當真實時間距離 `NOW` 超過 12 小時,所有以 `NOW` 種下的 session 一律被判
閒置過期 → 401。2026-08-29 03:31(= 距 `NOW` 14.5 小時)起,`services/identity`
**8/184 測試必然失敗**:「預期 200 得到 401」×5、「預期 403 得到 401」×2、
`Cannot read properties of undefined (reading 'last_seen_at')` ×1。

**它昨天是綠的,今天跨日後變紅**,與機器負載無關。W4 與總指揮各自獨立重現。

## Scope In
- 讓這些測試**不再依賴真實 wall-clock**。方式由開發者判斷,例如:
  `vi.useFakeTimers()` + `vi.setSystemTime(NOW)`;或讓 `NOW` 相對於
  `Date.now()` 產生;或讓 `seedSession` 的 `lastSeenAt` 預設為「現在」。
- **掃描 `services/**` 與 `apps/**` 是否有同類寫死日期的測試**,一併處理或
  在 EVIDENCE 列出清單說明為何其餘不受影響。

## Scope Out
- **不得修改 `SESSION_IDLE_LIMIT_MS`**——12 小時是產品行為,不是測試參數。
- 不改任何 production 邏輯。
- 不改 E2E spec。

## Functional Acceptance Criteria
1. `services/identity` 184/184 全綠。
2. **證明修正對日期不敏感**:以模擬時間推進的方式(例如 `faketime`、或在測試
   內以假時鐘把系統時間推到 `NOW + 30 天`)驗證測試仍全綠。**只證明「今天過了」
   不算達成**——那正是原缺陷的樣子。
3. 其餘套件既有測試零修改且全綠。

## Security / Authorization Acceptance
- 不得弱化 session 閒置/絕對過期的任何判定;既有 security-negative 測試
  (竄改、過期、disabled)零修改全綠。
