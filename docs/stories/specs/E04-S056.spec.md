# E04-S056 — `/v1/health` 在 dev/test 永遠回 `degraded`,`api-sandbox` E2E 因此永久紅

## Metadata
- Epic: E04(使用者增補追蹤範圍)
- Owner: Team A(W5,`apps/api` health + ASR 設定的 domain owner)
- MVP: **Required — 每條 lane 的每一次全量 E2E 都固定帶著這個失敗**
- Story size target: 0.5 developer-day

## ⚠️ 規格更正(總指揮 2026-08-29,W3 實測推翻原前提)

**本規格的原始前提是錯的,已作廢並改寫。** 原本寫「自 `ca7ef86` 起每條 lane
的每一次全量 E2E 都固定紅 `api-sandbox`」——W3 在未修正的樹上實跑
`pnpm exec playwright test api-sandbox --project=web`,結果 **4/4 全綠**。

原因:`tests/e2e/playwright.config.ts:163` 早在 **E03-S038**(`304c83f`)
就已設 `AI_KM_ASR_PROVIDER: "fake"`,而 api webServer 是
`reuseExistingServer: false`、獨佔 :4100,所以 Playwright 管理的路徑
**一直都是 fake ASR,`checkAsr` 對 fake 直接回 `ok`**。

**總指揮只讀了 `config.ts` 的預設值就宣稱 E2E 會紅,沒有實跑。**
這跟 2026-08-28 被撤回的 E04-S054 是同一種錯誤:從程式碼推論失敗模式,
沒有重現就下結論。W3 先查證再回報,擋下了一次照著錯前提做的實作。

## 問題陳述(改寫後,只列已實測確認的部分)

### 事實 A — 共用 :4000 回 `degraded`(已實測)

```
$ curl -s http://localhost:4000/v1/health
{"status":"degraded","version":"0.1.0","uptimeMs":30381333}
```

§5-penta 那個手動啟動的共用實例**沒有設 `AI_KM_ASR_PROVIDER`**,
走 `config.ts:165` 的預設 `whisper-server`,連不上 8178(`ss -ltn` 實測沒東西在聽)
→ `checkAsr` 回 `down` → `overallStatus` 回 `degraded`。

**但它目前不會讓任何 lane 的 E2E 變紅**,因為 E2E 走的是 :4100。

### 事實 B — §5-penta 的 preflight 攔不到(已實測)

現有 preflight 只看 `curl -w "%{http_code}"`。**`degraded` 一樣回 200**,
所以「共用 API 健康」這個檢查在 subsystem 掛掉時仍然通過。

### 事實 C — `api-sandbox.spec.ts:147` 耦合到選配子系統的營運狀態

該測試名為「apps/web's `/api/v1/health` rewrite reaches the real apps/api
instance」,要驗的是**路由**;斷言 `status: "ok"` 讓一個路由測試綁在 ASR
的死活上。今天不紅,是因為剛好有人設了 `fake`。

### 事實 D — `reuseExistingServer: true` 會讓 env 整組不生效(已查證,尚未證明造成過失敗)

`helpers/port-check.ts:18` → `resolveReuseExistingServer()` 回 `!process.env.CI`,
本機恆為 `true`。web/admin 兩個 webServer 因此**會直接沿用已在 :3000/:3001
跑著的 dev server**——而 Playwright 的 `env` 只套用在**它自己啟動的** server 上。

被沿用時,以下全部靜默失效:

```
API_INTERNAL_URL: http://127.0.0.1:4100        ← 可能還指著 :4000
NEXT_PUBLIC_CONVERSATIONS_PAGE_SIZE: "2"       ← E03-S046 靠它
NEXT_PUBLIC_FEATURE_MOCK_TRIGGERS: "true"      ← E03-S045 靠它
```

**這是四件事裡唯一可能造成過真實紅燈的**,而且症狀不像設定問題:
分頁大小回到 production 的 20,3 筆種子資料只有一頁,「下一頁」按鈕點了
不會導覽 → `page.waitForURL` 逾時 → **看起來就像機器太慢**。

> 🔬 **未證實的假說,必須實測才能寫進 EVIDENCE**:W6 在 E01-S025 回報的
> 12 個導覽逾時裡,`conversation-history-pagination` ×3 與 `model-selector` ×3
> 正好就是 `playwright.config.ts` 註解裡點名依賴 `PAGE_SIZE=2` 的那幾支。
> **這是巧合還是因果,總指揮沒有證據,不得當成已知結論轉述給任何人。**
> 唯一能定案的方法是實測(見 AC5)。

## Scope In
1. 讓 dev/test 環境下 `/v1/health` 能真實地回 `ok`(ASR 不是 dev 的硬相依)。
2. 讓 `api-sandbox.spec.ts:143` 斷言它真正要驗的東西(路由到達真 API)。
3. 確保「ASR 真的掛掉時 health 仍必須回 degraded」的能力**沒有被弱化**,
   且有測試證明。

## Scope Out
- 不改 `overallStatus` 的語意(E04-S047 AC1「任一 subsystem down → degraded」
  是正確的,不准為了讓測試變綠而放寬)。
- 不改 production 預設。`whisper-server` 作為 production 預設是正確的
  **fail-loud** 選擇,不得為了 dev 方便改成 `fake`(那是 fail-open,違反鐵律 2)。
- 不要求在 dev/test 真的跑起 whisper sidecar。

## 候選做法(實作者自行判斷並在 EVIDENCE 說明取捨)

**(a) dev/test 環境設 `AI_KM_ASR_PROVIDER=fake`**
`checkAsr` 對 `fake` 直接回 `ok`(`checks.ts:23-25`,既有行為,不用改碼)。
需要涵蓋**兩個**啟動路徑:playwright `webServer` 起的 API,以及 §5-penta
那個手動啟動的共用 `:4000` 實例(後者要同步更新 ROADMAP_TEMP 的啟動指令)。

**(b) 修正 `api-sandbox.spec.ts:143` 的斷言**
該測試的目的是路由,`status` 的**值**是它不該關心的耦合。

⚠️ **(b) 若單獨採用,等於放寬斷言** —— 依總指揮既有規則:
**移除斷言必須把覆蓋搬到正確的層級,不得淨減少覆蓋。** 要主張
「`ok` 已由別處驗證」就必須指名是哪個測試在驗,並確認它真的在驗。

總指揮的傾向是 **(a) + (b) 一起做**:(a) 讓 `ok` 在 dev 變成真的可達成,
(b) 讓路由測試不再耦合到選配子系統的營運狀態。只做 (a),下次任何子系統
在 dev 合理地 degraded 時同一條又會紅;只做 (b),dev 的 health 永遠顯示
degraded,那個雜訊本身就會掩蓋真問題。**但這是傾向,不是指令**——你有更好
的理由就照你的做,寫進 EVIDENCE。

## Functional Acceptance Criteria

- **AC1**:§5-penta 的共用 :4000 啟動指令補上 `AI_KM_ASR_PROVIDER=fake`,
  且 preflight 改成**檢查 body 的 `status` 欄位,不是只看 HTTP 200**。
  證據:重啟後 `curl -s :4000/v1/health` 回 `"status":"ok"`。
- **AC2**:`api-sandbox.spec.ts:143` 的斷言改成只驗它真正要驗的東西
  (路由到達真 apps/api),不再耦合 ASR 的營運狀態。
  ⚠️ **移除 `status: "ok"` 就必須指名接手驗證它的測試**,不得淨減少覆蓋。
- **AC3(反向驗證,依實測情況調整)**:原本要求「先貼修正前紅的輸出」。
  既然 W3 已實測該路徑本來就是綠的,**改為證明機制本身有效**:
  臨時 unset `AI_KM_ASR_PROVIDER` 跑一次,證明它確實會變 degraded/紅,
  再還原。**貼實際輸出,不得編造一個假的紅。**
- **AC4(不得弱化 fail-loud)**:證明 `asrProvider=whisper-server` 且
  sidecar 不可達時,health **仍然**回 `degraded`。既有
  `checks.test.ts`/`admin-health.test.ts` 若已涵蓋,指名即可。
- **AC5(事實 D,本 story 現在真正的重點)**:
  1. 讓 web/admin 兩個 webServer 在**沿用既有 server** 時不再靜默吞掉 env。
     做法自選(preflight 驗證既有 server 的 `API_INTERNAL_URL` 與兩個
     `NEXT_PUBLIC_*` 是否相符,不符就**大聲失敗**;或改成不沿用)。
     判準:**沿用一個設定不符的 server 必須明確報錯,不得靜默通過。**
  2. **實測那個假說**:故意先起一個指向 :4000、沒有 `PAGE_SIZE=2` 的
     web dev server,再跑 `conversation-history-pagination` 與
     `model-selector`,記錄失敗形狀。**若重現出 `waitForURL` 逾時,
     就證實了「設定漂移會偽裝成負載問題」**;若沒重現,誠實寫沒重現。
     兩種結果都要落檔——**這一條的價值在於得到答案,不在於答案是哪個。**

## Security / Authorization Acceptance
